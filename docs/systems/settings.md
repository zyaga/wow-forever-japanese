- **Registry API**: `define{ id, kind = "boolean" | "choice" | "key", default, label, ja, choices, choiceText, choiceHidden, normalize, check, group, hidden, apply }` (a duplicate id, an unknown kind, a `choice` without `choices` or a `key` without a `normalize` function raises); `get(id)`; `set(id, v) → true | false, reason` (`coerce` first: booleans and the strings `on/off/true/false/1/0`; a `choice` (lower-cased) must be in `choices`; a `key` is **not** lower-cased but passed to the definition's `normalize(v) → canonical | nil`, and nil fails with `expected a key (alt, lalt, button4, q, …)`). Then the optional `check(value) → ok, reason` refuses a valid value that conflicts with live client state: it runs on `set` only, never on `load` (load never consults the client). An invalid or refused value leaves the stored value untouched; a valid one is written to `WFJ_DB` and passed to the entry's `apply`. `list()` (definition order); `definition(id)` (the definition, with its labels and choice texts, or nil); `find(name)` (case-insensitive id lookup, used by slash); `isHidden(d)`: a definition's `hidden` is `true` or a function asked each time (the voice settings exist only while a voice pack is installed). A hidden setting stays readable and settable by slash; it is only left out of `/wfj`'s status list and the settings pages. Kinds: `boolean`, `choice` (`direction`, `voice.panel.size`, `voice.panel.style`, `words.saveClick` and `study.newPerDay`; an optional `choiceText` maps each choice to the English the settings page's dropdown shows, and an optional `choiceHidden(c)` leaves a choice out of that dropdown; only `words.saveClick` sets it, and its `check` refuses the same choices on `set`), `key`: no `number` kind (the collector cap is a constant, not a setting). `ja` is carried by every non-hidden definition (spec-enforced) and read only by the settings pages.
- **`apply` hooks**: `area.*` → `State.setArea(<area>)` (setting ids map onto State areas `quests` / `gossip` / `items` / `spells` / `ui` / `books`. `area.gossip` → `gossip`: the NPC talk window and the quest window's greeting prose (Forever's trainer window has no greeting); `area.books` → `books`: the book / letter / plaque window's page text; `area.interface` → `ui`: every interface-text record (tooltip structural lines, quest window / log headers and buttons, the greeting headers, the game menu); `area.itemTooltips` / `area.spellTooltips` govern only the description text, so turning one off leaves the structural lines Japanese); `marker.*` fire State event `markers` so open surfaces refresh; `readings.enabled` fires State event `readings(v)`: `UI/Readings` hides every cover frame at once when off and shows the attached ones again when on, no `/reload` ([Readings](readings.md)); `readings.glosses` fires State event `glosses(v)`: `UI/Readings` switches between the word card and the reading-only box and closes a card that is open, so the next hover shows the right one; `minimapButton` fires State event `minimapButton(v)`: `UI/MinimapButton` shows or hides the button ([Fix reports](fix-reports.md)); `voice.*` fire State event `voice()`: `UI/VoicePlayer` stops the line playing and hides the play / stop buttons until the next line ([Voice over](voice.md)); `modifier` → `Modifier.setKey`, which fires State `revealKey` (the save-click move listens to it, [below](#the-save-click-and-the-reveal-key)); `words.saveClick` fires State event `saveClick(v)`; `study.*` fire State event `study()`: `UI/StudyWindow` redraws the tab and the card, so the tab appears or goes, the cap changes what counts as waiting, and the combat setting takes effect at once ([Study](study.md)); `enabled` → `State.setEnabled`; `direction` → `State.setDirection`, which fires State `direction(v)` and then `language(english)` ([below](#the-direction-and-the-language-on-screen)). `Settings.loading` is true while `load` runs the applies, so a move made at load prints nothing.
- A new area (names, chat bubbles) is one `define` + one surface file; slash iterates the registry, and the settings pages place the new id in `Options.PAGES` (a spec fails until every non-hidden setting appears there exactly once). A changed default works the same way: a player who never set it gets the new default, one who turned it off keeps off. `area.interface` and `area.books` needed no migration: defaults live in `define`, so a `WFJ_DB` saved before them loads with them on; after a downgrade the stored key is unknown, preserved and never read.
- **SavedVariables**: `WFJ_DB` (settings; a few hundred bytes), `WFJ_Collector` (up to the 4 MiB cap; shape and its `disclosed` flag in [Collector](collector.md)), `WFJ_Log` (the problem log, [Diagnostics](diagnostics.md)) and `WFJ_Words` (the player's saved words, `{ schema, entries, everSaved }`, loaded with `step("words", …) or WFJ_Words` so a failed load never hands the client an empty list to write; [Word list](word-list.md)) and `WFJ_Study` (the study state of those words, `{ schema, cards, days }`, keys and numbers only, loaded after the list with the same guard; [Study](study.md)); a settings toggle never rewrites the dump, the word list or the study state. The study window's position is in `WFJ_DB.study.point`, not a setting. The toggle key lives in the client's binding set, never in `WFJ_DB`. `WFJ_DB` as shipped:
  ```lua
  WFJ_DB = { schema = 1, settings = { [id] = value }, backup = <the old table, on downgrade only>, build = { addon = "@project-version@" },
             minimap = { angle = <degrees around the minimap rim, absent until the button is dragged> },
             reports = { <pending fixes, see Fix reports> },
             collectorReminded = <UTC day number of the last collector reminder, absent until one shows>,
             intro = <false while a first install's welcome window is owed, true once shown or when the table existed before this key did>,
             asked = <false until the welcome window's question has been put to this account, then true> }
  ```
  `collectorReminded` is `math.floor(time() / 86400)` at the last reminder ([Collector](collector.md)). It lives here and not in `WFJ_Collector`, because the collector file may be attached to a public issue and holds no time on purpose. A new top-level field needs no schema bump: an older build keeps it and never reads it. `intro` and `asked` are set by `Core/Intro` at load and need no bump for the same reason ([Welcome window](#welcome-window)). `minimap` is written by `UI/MinimapButton` and `reports` by `Core/Reports` ([Fix reports](fix-reports.md)). Two fields of removed mechanisms, `timeRule` and `buffIdentity`, are deleted on load.
- **Load**: `Settings.load(db, schema, migrations) → db`; Main runs `WFJ_DB = WFJ.Settings.load(WFJ_DB, WFJ.SCHEMA, WFJ.Settings.MIGRATIONS)` on `ADDON_LOADED`. A `nil` table (first run) becomes `{ schema, settings = {} }`; a missing `schema` field is treated as current; a non-table `settings` is reset; a stored value that no longer coerces (`CTRL-Q`, `bogus key` for `modifier`) falls back to the default. Every entry's `apply` runs once with its effective value, so State mirrors the saved settings before any surface exists.
- **Migrations**: `Settings.MIGRATIONS[n]` runs on `db` while `db.schema < Const.SCHEMA`, one step at a time; a missing step is a no-op (the schema is additive). `db.schema > Const.SCHEMA` (downgrade) → the whole old table is kept under `WFJ_DB.backup`, settings reset, one line printed. Unknown keys preserved, never read.

### The direction and the language on screen
`direction` says which language the screen shows first ([ADR-081](../adr/081-english-first-and-english-word-cards.md)). `ja` (Japanese first, the default) is the addon as it always was: Japanese on screen, the [live English](../glossary.md) while the reveal key is held. `en` (English first) is the exact mirror: the client's English stays untouched on every surface the addon translates, and the Japanese shows while the key is held. The settings page calls the setting *Game text*; `/wfj direction ja|en` sets it like any setting.
- **One predicate.** `State.showsEnglish()` is `(State.direction == "en") ~= State.modifierHeld`: the direction crossed with the held key. `Modifier.english()` is the same from the polled key (`Modifier.isDown()`), for code that draws between two State events. Everything that picks a language asks one of the two, never the key.
- **One event.** State `language(english)` fires whenever what shows flips, by the key (`State.setModifierHeld`) or by the direction (`State.setDirection`). Every surface that follows the language listens to it. State `modifier(held)` still fires and is the key alone. `State.setDirection(v)` refuses anything but `ja` / `en` and an unchanged value; otherwise it fires `direction(v)`, then `language`.
- **The translator.** `Core/Translator.lua` takes the dep `showsEnglish` and returns `"leave", { english = true }` when English is what shows. The payload tells `UI/Render` that the untouched text is English on purpose, so it can attach [English word cards](readings.md#english-word-cards) there.
- **Who may read the key.** Only `Core/Modifier`, `Core/State`, `UI/RevealBinding`, `UI/KeyCapture`, `UI/Slash` and `Main.lua` read the held key. A test fails when any other file does (`tests/python/test_lint_gate.py`), so a new surface cannot follow the key and miss the direction.
- **Voice.** Nothing changes for the voice: a Japanese line never starts while English shows. In English first that means it is heard only while the key is held ([Voice over](voice.md)).

### The modifier
The key held to show the other language: the [live English](../glossary.md) in Japanese first, the Japanese in English first (`Core/Modifier.lua`; decision and alternatives in [ADR-018](../adr/018-reveal-key-override-binding.md)). `Modifier.normalize(v) → canonical | nil`, `class(k)`, `display(k)`, `PRESETS` (the nine polled values in page order), `bindingKey()`, `bindingEdge(down)`, `isDown()`, `english()`, `refresh()`, `setKey(k)`.

| Class | Values | Held = | Invalidation signal |
|---|---|---|---|
| `either` | `alt` `ctrl` `shift` | `IsAltKeyDown()` / `IsControlKeyDown()` / `IsShiftKeyDown()` | `MODIFIER_STATE_CHANGED` |
| `side` | `lalt` `ralt` `lctrl` `rctrl` `lshift` `rshift` | `IsLeftAltKeyDown()` … `IsRightShiftKeyDown()` [verified: RestrictedEnvironment.lua:86–88] | `MODIFIER_STATE_CHANGED` |
| `bound` | any other client key name, upper-case: `Q`, `F5`, `` ` ``, `NUMPAD1`, `-`, `BUTTON3`–`BUTTON5` | the `WFJ_REVEAL` binding saw `down` **and** the poll is still true: `IsKeyDown(key)` [verified: KeyCommand.lua:112]; mouse buttons `IsMouseButtonDown` (`BUTTON3` → `"MiddleButton"`, `BUTTON<n>` → `"Button<n>"` [likely: the client's mouse-button names, BindingUtil.lua:28–39; FrameXML only polls `"LeftButton"`; checklist 14d (In-game checklists, first list)]) | the `WFJ_REVEAL` binding's `keystate` down / up |

- **Normalization.** Lower-cased input that names a polled value returns it (`LAlt`, `lalt` and the client's `LALT` → `lalt`; `ALT` → `alt`). Anything else is upper-cased and accepted as `bound` when it is 1–16 printable bytes (`^[%w%p]+$`), not a chord (a `-` in a name longer than one byte; the minus key itself is the one-byte `-`), and not `BUTTON1`, `BUTTON2`, `ESCAPE`, `UNKNOWN`, or a meta name without a poll (`ALT`, `CTRL`, `SHIFT`, `META`, `LMETA`, `RMETA`). Keys with no held state to poll are refused too: `MOUSEWHEEL*`, gamepad `PAD*`, and `BUTTON6` and up. `display(k)` is the English name of a preset (`Left Alt`); a `bound` key is returned raw and the UI passes it through `GetBindingText`. Key names stay English ([principle 2](../architecture/principles.md#2-names-stay-in-english)).
- **Taking a `bound` key over** (`UI/RevealBinding.lua`). `Modifier.setKey(k)` stores the canonical value, clears the binding edge and fires State event `revealKey(k)` on every apply; `RevealBinding` subscribes (Core never calls binding APIs). `apply()` calls `ClearOverrideBindings(owner)` on its one hidden frame, then, for a `bound` key only, `SetOverrideBinding(owner, true, key, "WFJ_REVEAL")` (priority) [verified present: RestrictedFrames.lua:24–28]. `either` / `side` keys get no binding, so a bare Alt needs no binding. While the addon is loaded the key's own action (action button 5 on `Q`) does not fire; it returns when the modifier changes or the addon is disabled. `RevealBinding.state` = `none` (polled) · `applied` · `queued`. Main calls `RevealBinding.apply()` again on `PLAYER_ENTERING_WORLD` when `isInitialLogin` or `isReloadingUi`, in case the client loads bindings after `ADDON_LOADED`.
- **Held state for `bound`.** `WFJ_RevealKey(keystate)` → `Modifier.bindingEdge(keystate == "down")` → `refresh()`, then `RevealBinding.watch(held)`: while held, an `OnUpdate` on the owner frame calls `Modifier.refresh()` each frame and clears itself once the poll reads up. A binding does not fire while an EditBox has focus, so typing the key in chat sets no edge and reveals nothing; a key-up that never arrives (focus left mid-hold) is caught by the poll, which clears the edge.
- **Combat.** Binding calls are restricted in combat [likely: RestrictedFrames usage]. With `InCombatLockdown()`, `apply` only records a pending change (`state = "queued"`); Main routes `PLAYER_REGEN_ENABLED` to `RevealBinding.flush()`, which applies it once. At most one pending apply: the latest value wins.
- **Conflict with the toggle key.** The `modifier` definition's `check` (`notToggleKey`) refuses a value equal (case-insensitive, exact key; the chord `CTRL-J` does not conflict with `J`) to any key `GetBindingKey("WFJ_TOGGLE")` returns: `<key> is already the key for turning translation on / off`. `GetBindingKey` is reached through `Compat.resolve`, so Core stays frame-free; when it is absent nothing is refused. The reverse direction (a toggle key equal to the modifier) is refused on the settings page.

### The save click and the reveal key
`words.saveClick` ([Word list](word-list.md)) is never the reveal key's own modifier: holding that key shows the other language, so the word under the pointer is no longer the one highlighted. Cmd (`meta`) exists only on a Mac client (`IsMacClient`, read through `Compat`).
- **Hidden choices.** `Words.hidden(choice, revealKey, isMac)`: the Ctrl family (`ctrl`, `lctrl`, `rctrl`) hides `ctrl`; the Shift family hides `shift`; the Alt family and `bound` keys hide nothing; `meta` is hidden off a Mac. The settings page asks the definition's `choiceHidden` each time the dropdown opens, so it follows the reveal key; the definition's `check` refuses a hidden choice on `Settings.set` (slash included).
- **The move.** `Core/Settings` listens to State `revealKey`, which `Modifier.setKey` fires on every apply of the modifier, at load too. When the stored save click is now hidden, the listener writes the first free choice in the order `ctrl`, `shift`, `meta`, `click` (`Words.nextFree`) into `WFJ_DB` and fires State `saveClick` (so `UI/WordSave`'s cached choice follows). A stored clash, or a stored `meta` on a non-Mac client, is moved at load without a chat line; a move after load also fires `saveClickMoved`, and `UI/WordSave` prints `Saving a word now uses Shift+click.` in both languages.

### Settings pages
- **Four canvas pages, and a fifth with a voice pack** (`UI/Options.lua`), in this order: main, words, voice, collector, about. A page's rows sit on a body frame inside the client's scroll frame (`ScrollFrameTemplate`), so a page is as tall as its rows need and scrolls when it is taller than the panel; the scroll bar hides while the page fits. Rows are 596 px wide, which leaves room for the bar. Sections are 26 px apart (`SECTION_GAP`; a section may set its own `gap`). Side-by-side sections (two or three columns) are kept. Explanations are one or two lines.
  - **Title and Defaults.** Each page starts with its title (one language, gold, 18 px). Every page except About has a **Defaults** button (初期設定に戻す, 110 px) at the right of the title. The first click relabels it `Click again to reset this page`; a second click within 5 s (by `GetTime`) sets every setting placed on that page, and no other, back to its `define` default through `Settings.set`, then refreshes the page. Hiding the page disarms it. A hidden setting is skipped, and the reveal key is refused in combat like any other change to it. The toggle key is a binding, not a setting, so Defaults leaves it alone.
  - **main**: the tagline under the title. The `mainWelcome` row: one line (*Studying Japanese, studying English or just playing? ### Key capture
`UI/KeyCapture.lua`: `KeyCapture.new(parent, { mode = "reveal" | "toggle", width, onKey, onRefused })`. Clicking the button starts a capture (refused while `InCombatLockdown()`) and relabels it **キーを押す** (Press a key; one language at a time). The capture buttons use the key-binding button art (`UIMenuButtonStretchTemplate`). **Handlers exist only while listening**: `start` sets `OnKeyDown` / `OnMouseDown` and `EnableKeyboard(true)`; `stop` clears `OnKeyDown`, puts back the template's own `OnMouseDown` (its pressed look, also called while listening) and calls `EnableKeyboard(false)`, Blizzard's `KeybindListener:SetListening` pattern [verified: Blizzard_Keybindings.lua:26–40]. A frame with an `OnKeyDown` script takes keyboard input whenever it is visible: standing handlers on the pages would swallow Escape, and the game menu would not open. One capture listens at a time (`KeyCapture.active`; starting one stops the other). Input is converted with `GetConvertedKeyOrButton` [verified: BindingUtil.lua:66]. Escape, a second click or `OnHide` (hooked; leaving the page) cancel; `BUTTON1` / `BUTTON2` are ignored so the starting click cannot bind itself.
- **reveal** (idle label **変更** / Change): the key goes through `Modifier.normalize` with modifier state ignored: a lone `LALT` completes as `lalt`, `Q` as `Q`, `Button4` as `BUTTON4`; the result is `Settings.set("modifier", …)`, applied immediately even when the key has an action (the warning line names it).
- **toggle** (idle label **キーを設定** / Set key): meta keys alone keep the capture waiting; the key completes as `CreateKeyChordStringUsingMetaKeyState(key)` [verified: BindingUtil.lua:116], so `CTRL-J` is allowed. A key equal to the modifier is refused (`<key> is already the key for showing English.`). A key with another action waits for **Replace** (`<key> is used for “<action>”. Replace it?`); a free key is written at once. Replace re-checks the modifier (`Options.unbindOrReplace`): if the modifier moved onto the pending key meanwhile, it writes nothing and shows the refusal. On refresh, a toggle key equal to the modifier's key (bound later in Key Bindings) shows `<key> is already the key for showing English.` `KeyCapture.setToggle(key)`: `SetBinding(old)` for each current `WFJ_TOGGLE` key, `SetBinding(key, "WFJ_TOGGLE")`, `SaveBindings(GetCurrentBindingSet())`: a real saved binding, the same as Blizzard's Key Bindings UI; when `SetBinding` refuses the new key, the old keys are put back and nothing is saved (→ false). **Unbind** (`clearToggle`) clears every current key and saves. Both refuse in combat.
- **Conflicts**: `KeyCapture.conflict(key, ours)` = `GetBindingAction(key)` when non-empty and not `ours`, shown as `GetBindingText(action, "BINDING_NAME_")`. `GetBindingAction` without `checkOverride` reads the saved binding, so a key the addon took over still names its own action [likely: the client only ever passes nil there, Blizzard_Keybindings.lua:127; checklist 14c (In-game checklists, first list)].

### Welcome window
One window asks every player what they are here for, once (`Core/Intro.lua` decides when, `UI/IntroWindow.lua` draws it; the file and function names keep the older word, intro). A first install sees it at its first login or reload. A player who already had the addon sees it once too, the first time a version that asks the question loads: nobody has answered it yet. Showing the window changes no setting ([ADR-081](../adr/081-english-first-and-english-word-cards.md)).
- **The flags.** Main reads `type(WFJ_DB) ~= "table"` before the settings step creates the table. The `intro.prepare` step then runs `Intro.prepare(db, fresh)`: with no `intro` key, a fresh load writes `false` (owed) and an existing table writes `true`; with no `asked` key it writes `false` for everyone. A downgrade reset replaces the table, but a table existed, so it is not fresh.
- **When it shows.** On `PLAYER_ENTERING_WORLD` with login or reload, an `intro` step after `collectorremind` runs `Intro.run(db, IntroWindow.request)`: when `intro` or `asked` is `false` it writes both `true` first, then asks for the window. A zone change never opens it. The window opens a second later, never in the login event itself: the client closes every special window on its own `PLAYER_ENTERING_WORLD`, when a cinematic starts (a new character's race intro) and when the interface comes back after one. While a cinematic plays it waits, and a cinematic that hid it brings it back when it ends; a hide outside a cinematic (Start, Esc) is the player's, and it stays closed. Writing the flags first means a window that fails to build is caught by the step guard (`initErrors` lists `intro`) and does not come back at every login; the collector reminder has already run. The flags reach disk when the game saves its settings at logout or reload, so a first session that ends in a crash shows the window again next time.
- **Page one: the question.** Title *WoW Forever Japanese*. The question *どのように使いますか？* (gold) with *What are you here for?* under it, then three cards side by side, each with one of the client's own icons (a scroll, a book, a sword), an English label and a Japanese one: **Study Japanese** / 日本語を学ぶ, **Study English** / 英語を学ぶ, **Just play** / 日本語で遊ぶ. Under them, *You can change this later in the settings.* in both languages and the **決定 / Confirm** button. Selecting a card writes nothing.

  | Choice | `direction` | `readings.enabled` (word cards) | `study.tab` |
  |---|---|---|---|
  | Study Japanese | `ja` | on | on |
  | Study English | `en` | on | on |

  Nothing else is written, and each of the three is an ordinary setting the settings pages also show.

Opened by hand it starts on the choice the settings match: `direction` and `readings.enabled` decide (the study tab does not: a learner who hid it is still a learner), and settings that match no choice (English first with the cards off) start on Study Japanese.

## Invariants
- Defaults exist only in `define`. Account-wide only (no per-character profiles) in v1.
- A settings-schema change needs a migration and a test. The `key` kind needed no schema bump: every older stored value (`alt` / `ctrl` / `shift`) normalizes to itself, and `WFJ_DB` stays schema 1.
- The player's saved bindings are written only by an explicit toggle-key action on the settings page (Set key, Replace, Unbind) or `/wfj togglekey` (the same refusals and a typed-again Replace); the modifier never writes them.
- The modifier and the toggle key never share a key (refused in both directions; Replace re-checks at click time).
- A settings frame has `OnKeyDown` / keyboard input only while its capture is listening, and at most one capture listens.

## Edge cases
- `alt` matches `LALT` and `RALT` (etc.); `lalt` matches only the left key. Changing the modifier while held → `State.modifierHeld=false`, fire (the binding edge is cleared too).
- Downgrade to a build without the `key` kind: a stored `lalt` / `Q` / `BUTTON4` fails its `choice` coerce and the old build falls back to Alt; `WFJ_DB` needs no reset. A toggle key set from the page is an ordinary `WFJ_TOGGLE` binding and keeps working.
- Override bindings are session-only [likely: their documented purpose; checklist 14c (In-game checklists, first list)]: disabling the addon and `/reload` gives a taken-over key its action back, and nothing stays bound.
- Typing a `bound` key in an EditBox reveals nothing (the binding does not fire while an EditBox has focus).
- A lost key-up (the window lost focus mid-hold) is cleared by the watcher's poll, so English does not stay on.
- A `bound` modifier set by slash in combat is queued and applied once on `PLAYER_REGEN_ENABLED` (a polled key applies at once); the page refuses modifier changes in combat (dropdown and captures disabled), and a capture open when combat starts is cancelled.
- The reveal key set to Ctrl while the save click is Ctrl+click: the save click moves to Shift+click (or the next free choice) with one chat line; setting the reveal key back does not move it back.
- Escape and chat typing are never taken by the pages: no key handler exists outside an active capture, and pages stay hidden until the Settings panel shows them.
- The player later binds the `bound` modifier key to something in Blizzard's UI: the priority override still wins while loaded; the page shows the takeover warning on its next show. A toggle key rebound elsewhere shows live on the next show (`GetBindingKey`).
- Modifier equal to the toggle key: `Settings.set` refuses it (slash and page); a toggle capture equal to the modifier is refused on the page. Only an exact key conflicts (`J` and `CTRL-J` coexist).
