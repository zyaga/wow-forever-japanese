# Settings

> Registry, SavedVariables, the modifier, settings pages, slash, keybindings. Code: `Core/Settings.lua`, `Core/Modifier.lua`, `UI/Options*.lua`, `UI/RevealBinding.lua`, `UI/KeyCapture.lua`, `UI/AddonListButton.lua`, `UI/Slash.lua`, `Bindings.xml`. ## How it works
```lua
-- Core/Settings.lua, `-- Definitions` section. `apply` closures resolve their modules at call time. `ja` is
-- the Japanese the settings page shows for the English `label` (one language at a time): addon
-- interface copy, not game text.
Settings.define{ id="enabled",             kind="boolean", default=true,  label="Enable translation", ja="翻訳を有効にする", apply=function(v) WFJ.State.setEnabled(v) end }
Settings.define{ id="modifier",            kind="key",     default="alt", label="Hold to show English", ja="押している間は英語で表示",
                 normalize=function(v) return WFJ.Modifier.normalize(v) end, check=notToggleKey, apply=function(v) WFJ.Modifier.setKey(v) end } -- kind "key" (ADR-018)
Settings.define{ id="area.quests",         kind="boolean", default=true,  group="areas", label="Quest windows & log",  ja=…, apply=area("quests") }
Settings.define{ id="area.gossip",         kind="boolean", default=true,  group="areas", label="NPC talk", ja=…, apply=area("gossip") }
Settings.define{ id="area.itemTooltips",   kind="boolean", default=true,  group="areas", label="Item tooltips",        ja=…, apply=area("items") }
Settings.define{ id="area.spellTooltips",  kind="boolean", default=true,  group="areas", label="Spell tooltips",       ja=…, apply=area("spells") }
Settings.define{ id="area.interface",      kind="boolean", default=true,  group="areas", label="Interface text (buttons, headers, tooltip lines)", ja=…, apply=area("ui") }
Settings.define{ id="area.books",         kind="boolean", default=true,  group="areas", label="Books & letters",      ja="本と手紙", apply=area("books") }
Settings.define{ id="marker.stale",        kind="boolean", default=true,  label="Mark translations whose English changed", ja=…, apply=markers }
Settings.define{ id="marker.missing",      kind="boolean", default=true,  label="Mark untranslated text", ja=…, apply=markers } -- on by default
Settings.define{ id="readings.enabled",    kind="boolean", default=true,  label="Show readings when hovering a word", ja="単語にカーソルを合わせると読み方を表示",
                 apply=function(v) WFJ.State.fire("readings", v) end } -- on by default; nothing is drawn until the mouse is on a word
Settings.define{ id="readings.glosses",    kind="boolean", default=true,  label="Show word meanings in the reading box", ja="読み方の枠に単語の意味を表示",
                 apply=function(v) WFJ.State.fire("glosses", v) end } -- the word card: meanings on or off
Settings.define{ id="minimapButton",       kind="boolean", default=true,  label="Show the minimap button (report a line)", ja="ミニマップにボタンを表示（翻訳の報告）",
                 apply=function(v) WFJ.State.fire("minimapButton", v) end } -- the fix-report minimap button, on by default
-- Defined by Core/Collector.lua, not by Core/Settings.lua; no `apply`; the collector reads it at record time:
Settings.define{ id="collector.enabled",   kind="boolean", default=true,  label="Record English for future translations", ja="今後の翻訳のために英語テキストを記録する" }
```
- **Registry API**: `define{ id, kind = "boolean" | "choice" | "key", default, label, ja, choices, normalize, check, group, hidden, apply }` (a duplicate id, an unknown kind, a `choice` without `choices` or a `key` without a `normalize` function raises); `get(id)`; `set(id, v) → true | false, reason` (`coerce` first: booleans and the strings `on/off/true/false/1/0`; a `choice` (lower-cased) must be in `choices`; a `key` is **not** lower-cased but passed to the definition's `normalize(v) → canonical | nil`, and nil fails with `expected a key (alt, lalt, button4, q, …)`). Then the optional `check(value) → ok, reason` refuses a valid value that conflicts with live client state: it runs on `set` only, never on `load` (load never consults the client). An invalid or refused value leaves the stored value untouched; a valid one is written to `WFJ_DB` and passed to the entry's `apply`. `list()` (definition order); `find(name)` (case-insensitive id lookup, used by slash). Kinds: `boolean`, `choice` (no definition uses it; kept for the registry), `key`: no `number` kind (the collector cap is a constant, not a setting). `ja` is carried by every non-hidden definition (spec-enforced) and read only by the settings pages.
- **`apply` hooks**: `area.*` → `State.setArea(<area>)` (setting ids map onto State areas `quests` / `gossip` / `items` / `spells` / `ui` / `books`. `area.gossip` → `gossip`: the NPC talk window and the quest window's greeting prose (Forever's trainer window has no greeting); `area.books` → `books`: the book / letter / plaque window's page text; `area.interface` → `ui`: every interface-text record (tooltip structural lines, quest window / log headers and buttons, the greeting headers, the game menu); `area.itemTooltips` / `area.spellTooltips` govern only the description text, so turning one off leaves the structural lines Japanese); `marker.*` fire State event `markers` so open surfaces refresh; `readings.enabled` fires State event `readings(v)`: `UI/Readings` hides every cover frame at once when off and shows the attached ones again when on, no `/reload` ([Readings](readings.md)); `readings.glosses` fires State event `glosses(v)`: `UI/Readings` switches between the word card and the reading-only box and closes a card that is open, so the next hover shows the right one; `minimapButton` fires State event `minimapButton(v)`: `UI/MinimapButton` shows or hides the button ([Fix reports](fix-reports.md)); `modifier` → `Modifier.setKey`; `enabled` → `State.setEnabled`.
- A new area (names, chat bubbles) is one `define` + one surface file; slash iterates the registry, and the settings pages place the new id in `Options.PAGES` (a spec fails until every non-hidden setting appears there exactly once). A changed default works the same way: a player who never set it gets the new default, one who turned it off keeps off. `area.interface` and `area.books` needed no migration: defaults live in `define`, so a `WFJ_DB` saved before them loads with them on; after a downgrade the stored key is unknown, preserved and never read.
- **Two SavedVariables**: `WFJ_DB` (settings; a few hundred bytes) and `WFJ_Collector` (up to the 4 MiB cap; shape and its `disclosed` flag in [Collector](collector.md)); a settings toggle never rewrites the dump. The toggle key lives in the client's binding set, never in `WFJ_DB`. `WFJ_DB` as shipped:
  ```lua
  WFJ_DB = { schema = 1, settings = { [id] = value }, backup = <the old table, on downgrade only>, build = { addon = "@project-version@" } }
  ```
- **Load**: `Settings.load(db, schema, migrations) → db`; Main runs `WFJ_DB = WFJ.Settings.load(WFJ_DB, WFJ.SCHEMA, WFJ.Settings.MIGRATIONS)` on `ADDON_LOADED`. A `nil` table (first run) becomes `{ schema, settings = {} }`; a missing `schema` field is treated as current; a non-table `settings` is reset; a stored value that no longer coerces (`CTRL-Q`, `bogus key` for `modifier`) falls back to the default. Every entry's `apply` runs once with its effective value, so State mirrors the saved settings before any surface exists.
- **Migrations**: `Settings.MIGRATIONS[n]` runs on `db` while `db.schema < Const.SCHEMA`, one step at a time; a missing step is a no-op (the schema is additive). `db.schema > Const.SCHEMA` (downgrade) → the whole old table is kept under `WFJ_DB.backup`, settings reset, one line printed. Unknown keys preserved, never read.

### The modifier
The key held to show the [live English](../glossary.md) (`Core/Modifier.lua`; decision and alternatives in [ADR-018](../adr/018-reveal-key-override-binding.md)). `Modifier.normalize(v) → canonical | nil`, `class(k)`, `display(k)`, `PRESETS` (the nine polled values in page order), `bindingKey()`, `bindingEdge(down)`, `isDown()`, `refresh()`, `setKey(k)`.

| Class | Values | Held = | Invalidation signal |
|---|---|---|---|
| `either` | `alt` `ctrl` `shift` | `IsAltKeyDown()` / `IsControlKeyDown()` / `IsShiftKeyDown()` | `MODIFIER_STATE_CHANGED` |
| `side` | `lalt` `ralt` `lctrl` `rctrl` `lshift` `rshift` | `IsLeftAltKeyDown()` … `IsRightShiftKeyDown()` [verified: RestrictedEnvironment.lua:86–88] | `MODIFIER_STATE_CHANGED` |
| `bound` | any other client key name, upper-case: `Q`, `F5`, `` ` ``, `NUMPAD1`, `-`, `BUTTON3`–`BUTTON5` | the `WFJ_REVEAL` binding saw `down` **and** the poll is still true: `IsKeyDown(key)` [verified: KeyCommand.lua:112]; mouse buttons `IsMouseButtonDown` (`BUTTON3` → `"MiddleButton"`, `BUTTON<n>` → `"Button<n>"` [likely: the client's mouse-button names, BindingUtil.lua:28–39; FrameXML only polls `"LeftButton"`; checklist 14d (In-game checklists, first list)]) | the `WFJ_REVEAL` binding's `keystate` down / up |

- **Normalization.** Lower-cased input that names a polled value returns it (`LAlt`, `lalt` and the client's `LALT` → `lalt`; `ALT` → `alt`). Anything else is upper-cased and accepted as `bound` when it is 1–16 printable bytes (`^[%w%p]+$`), not a chord (a `-` in a name longer than one byte; the minus key itself is the one-byte `-`), and not `BUTTON1`, `BUTTON2`, `ESCAPE`, `UNKNOWN`, or a meta name without a poll (`ALT`, `CTRL`, `SHIFT`, `META`, `LMETA`, `RMETA`). Keys with no held state to poll are refused too: `MOUSEWHEEL*`, gamepad `PAD*`, and `BUTTON6` and up. `display(k)` is the English name of a preset (`Left Alt`); a `bound` key is returned raw and the UI passes it through `GetBindingText`. Key names stay English ([principle 2](../architecture/principles.md#2-names-stay-in-english)).
- **Taking a `bound` key over** (`UI/RevealBinding.lua`). `Modifier.setKey(k)` stores the canonical value, clears the binding edge and fires State event `revealKey(k)` on every apply; `RevealBinding` subscribes (Core never calls binding APIs). `apply()` calls `ClearOverrideBindings(owner)` on its one hidden frame, then, for a `bound` key only, `SetOverrideBinding(owner, true, key, "WFJ_REVEAL")` (priority) [verified present: RestrictedFrames.lua:24–28]. `either` / `side` keys get no binding, so a bare Alt needs no binding. While the addon is loaded the key's own action (action button 5 on `Q`) does not fire; it returns when the modifier changes or the addon is disabled. `RevealBinding.state` = `none` (polled) · `applied` · `queued`. Main calls `RevealBinding.apply()` again on `PLAYER_ENTERING_WORLD` when `isInitialLogin` or `isReloadingUi`, in case the client loads bindings after `ADDON_LOADED`.
- **Held state for `bound`.** `WFJ_RevealKey(keystate)` → `Modifier.bindingEdge(keystate == "down")` → `refresh()`, then `RevealBinding.watch(held)`: while held, an `OnUpdate` on the owner frame calls `Modifier.refresh()` each frame and clears itself once the poll reads up. A binding does not fire while an EditBox has focus, so typing the key in chat sets no edge and reveals nothing; a key-up that never arrives (focus left mid-hold) is caught by the poll, which clears the edge.
- **Combat.** Binding calls are restricted in combat [likely: RestrictedFrames usage]. With `InCombatLockdown()`, `apply` only records a pending change (`state = "queued"`); Main routes `PLAYER_REGEN_ENABLED` to `RevealBinding.flush()`, which applies it once. At most one pending apply: the latest value wins.
- **Conflict with the toggle key.** The `modifier` definition's `check` (`notToggleKey`) refuses a value equal (case-insensitive, exact key; the chord `CTRL-J` does not conflict with `J`) to any key `GetBindingKey("WFJ_TOGGLE")` returns: `<key> is already the key for turning translation on / off`. `GetBindingKey` is reached through `Compat.resolve`, so Core stays frame-free; when it is absent nothing is refused. The reverse direction (a toggle key equal to the modifier) is refused on the settings page.

### Settings pages
- **Three canvas pages** (`UI/Options.lua`), laid out to fit 640 × 560 (spec-enforced from recorded anchors and sizes), so no page scrolls:
  - **main**: header line `v<version> · <memory> · data: 4,536 quests · 9,047 items · 8,284 spells · 13,392 UI strings` (memory via `Compat.memoryKB`, counts from `WFJ.Data.meta.counts`, `data: none` when no `Meta.lua` is loaded) and the tagline. *Translation*: `enabled` with `readings.enabled` beside it in a second column, and `readings.glosses` (*Show word meanings in the reading box*) as the section's second row (the *What to translate* section uses three columns so the page still fits 640 × 560; the section continues in an untitled section with `gap = 0`, a per-section override of the 10px gap); the modifier row: a dropdown of the nine presets, plus the stored key as a checked extra item when the value is `bound`, a capture button (105px), and a full-width warning line under the row (x, y − 26); the row is 48px. The toggle key row (36px high; its rare warning line sits in the section gap): the current key at size 12 (`GetBindingKey("WFJ_TOGGLE")` through `GetBindingText`, or 未設定 / `Not set`), a capture button (**Set key**, 105px) with **Unbind** (95px, relabelled **Replace** while a conflicting key waits for confirmation) beside it on the same line, and a warning line under the label (380px wide) (layout checked in game). *What to translate*: the six `area.*` checkboxes in three columns, two rows: Quest windows & log · NPC talk · Books & letters, then Item tooltips · Spell tooltips · Interface text (each column `floor(620 / 3)` wide; the quests label's Japanese shortened to クエストウィンドウとログ so it fits). *Markers*: `marker.stale` / `marker.missing` in one column, each label stopping at 390px before its marker sample at x + 400 in the marker colour. The `minimapButton` checkbox fills the glosses row's second column.
  - **collector** (category name *English Collector*). *Collector*: the two-line explanation, `collector.enabled`, the status line in the page's language (`collector.status` + `collector.statusLine` with `collector.on` / `off`, and `· full` / `· paused` / `· N errors` from `collector.full` / `paused` / `errors`, built from `Collector.status()`; `/wfj collector status` keeps `Collector.describe()`'s English), **Clear collected English** (the first click only re-labels it `Click again to clear N entries`; a second click within 5 s, by `GetTime`, calls `Collector.clear()` and shows `Cleared N entries`, or restores **Clear collected English** when `clear()` returns nil, a dump from a newer version that is never cleared; an armed label goes back on the first refresh after the 5 s, or on hiding the page). *Sending it in*: the four numbered send steps (`collector.steps`: click Send English, copy the link and open it in a browser, paste the second box's text if the window shows one, submit the issue then click I sent it), the **Send English** button (160px; `CollectorSendWindow.open(false)`, the send window, [Collector](collector.md)), and the SavedVariables path in a copy box, labelled as the file to attach (zipped) when a send is too long to paste. The path is `Collector.path()`, read when the page is built: `_classic_beta_` in place of `<client folder>` on a beta client (`IsBetaBuild()`). The page is the UI for `/wfj collector` ([Collector](collector.md)).
  - **about** (category name *About & Help*): the header line; *How it works*: holding the key, pointing at a word for its reading (`about.readings`), the stale marker, how to open these settings; *Slash commands*: the grammar as an English list (`OptionsText.SLASH`; it names every top-level verb and every `debug` sub-verb, which `options_spec` checks); a **Report a line** row whose button opens the fix window ([Fix reports](fix-reports.md)); then *Other problems (bugs, suggestions)* / その他の問題（不具合・要望） with the issue tracker's link (`…/issues/new/choose`) in a copy box.
- **No page links.** The Settings panel's own category list switches between the three pages; page buttons would be a second, redundant way. `Compat.registerOptions` calls `SetExpanded(true)` on the addon's category, so *English Collector* and *About & Help* are listed under it without clicking its toggle [verified: `SettingsCategoryMixin:SetExpanded`, Blizzard_Category.lua:114; the list reads `IsExpanded`, Blizzard_CategoryList.lua:102]. `Compat.openOptions(page)` still opens a page by id (`/wfj config`). The addon never writes Blizzard's category tables.
- **Layout is declared, not definition order.** `Options.PAGES` = page → sections → rows (`columns = 1 | 2 | 3`, optional `gap` below the section, default 10); a row is a setting id (`boolean` → checkbox, `key` → the modifier row) or a named builder in `Options.ACTIONS` (`toggleKey`, `collectorExplain`, `collectorStatus`, `collectorClear`, `collectorSteps`, `collectorSend`, `collectorPath`, `aboutHold`, `aboutReadings`, `aboutMarkers`, `aboutOpen`, `slashHelp`, `aboutFix`, `reportLink`). Every non-hidden setting appears exactly once and every row id is a setting or an action (spec-enforced).
- **One language at a time** (`UI/OptionsWidgets.lua`). The pages show one language at a time because both at once are harder to read in game. `W.pick(en, ja)` returns the Japanese, or the English when translation is off (`State.enabled == false`) or the reveal key is held (`Modifier.isDown()`): the rule the game text follows. `W.label` (one FontString, wrapping at its width; a row is `W.ROW` = 30px), section headers, checkboxes and `W.button` captions hold both texts and re-show the current one through `W.relabel`, run on the State `modifier` and `enabled` events (`W.setPair` changes a label's texts). The page title is one language, gold, 18px. All copy is set with `W.put`: the bundled font at a fixed size in either language (the client's default fonts have no Japanese [likely: no `japanese` alphabet in Fonts.xml]), so nothing changes size when the language flips. Setting labels come from each definition's `label` / `ja`; every other string on the pages lives in `UI/OptionsText.lua` (`T[key] = { en, ja }`, `Text.get(key, ...)` formats both with the same `%s` arguments; a missing key raises). The category list shows English names only (it has no Japanese font). The copy is addon interface text: no `data/` entry, no provenance. Rows with long copy (the About help lines, the collector explanation, the copy-box labels) take `W.labelHeight(label, minimum)`, the measured height (`GetStringHeight`, [likely]) plus 12, so a wrapped line never runs into the next row.
- **Client templates**: the widgets Forever's own settings use [verified: forever-ui-1.60.1.70009]: section headers on `SettingsListSectionHeaderTemplate` (Blizzard_SettingControls.xml:12) with a gold title (15px), a faint band behind it and a gold rule under it; checkboxes on `MinimalCheckboxTemplate` (CheckButtonTemplates.xml:74, 24px, label to the right); `UIPanelButtonTemplate` (SharedUIPanelTemplates.xml:315): its label is left empty and our own FontString (one language, size 11, gold / grey when disabled) sits over it, because the template swaps its label's font object on hover / disable, which would drop the bundled font (the same case `UI/ButtonText` handles); `W.button(parent, en, ja, width, onClick, template)` keeps `width` as `minWidth`, widens to the caption plus `W.BUTTON_PAD` (16px) each side on every `setLabel`, and takes another button art when `template` is given (the capture buttons: `UIMenuButtonStretchTemplate`, the key-binding button's base, SharedUIPanelTemplates.xml:772); `InputBoxTemplate` (InputBoxTemplates.xml:70) as read-only copy boxes whose text snaps back after any edit and highlights on focus; `WowStyle1DropdownTemplate` (MenuTemplates.xml:3) with `SetupMenu` / `CreateRadio`. The build stays `pcall`ed in Main, and `/wfj debug` prints `settings panel failed to build: <error>`.
- **Refresh.** Pages are built hidden (`page:Hide()`; a parentless frame is visible); the Settings panel shows a canvas when its category is selected and hides it on leaving [verified: Blizzard_SettingsPanel.lua:866–909]. Each page's `OnShow` fills the header line (version · memory · data counts) and re-reads every control from `Settings.get` and the live binding state, so a slash-side change shows on the next show. State events `enabled`, `area`, `markers`, `readings` and `revealKey`, and combat start / end, refresh only while a page `IsVisible()`. `UpdateAddOnMemoryUsage` is expensive (AddonList.lua:761), so memory is read in `OnShow` only, never on a refresh, a combat change or a toggle press. `OnHide` calls `Options.forgetPending()`: a pending Replace, its note and a refused-capture note are dropped. The modifier row's warning shows, in priority order: the combat notice; the toggle conflict after a refused capture; `<key> takes effect after combat` while a change is queued; for a `bound` key that has an action in the player's binding set, `<key> is used for “<action>”. While this addon is loaded, <key> shows English instead.`
- **Combat.** Main routes `PLAYER_REGEN_DISABLED` / `ENABLED` to `Options.setCombat(flag)`, which stores `Options.inCombat`; `InCombatLockdown()` may still read false inside `PLAYER_REGEN_DISABLED`, so the page treats either as combat. Entering combat stops any open capture; while in combat the modifier dropdown, both capture buttons and Unbind are disabled, a page-side modifier change (`Options.setModifier`) is refused, and both warning lines read `Keys can't be changed in combat.`
- **Registration.** `Compat.registerOptions(pages)` takes the ordered `{ { id, frame, name } }` list `Options.build()` returns: the first page → `Settings.RegisterCanvasLayoutCategory`; the rest → `Settings.RegisterCanvasLayoutSubcategory(parent, frame, name)` (returns the subcategory [verified: SettingsInbound.lua:99–102]); then `Settings.RegisterAddOnCategory(parent)` last: "the last step" in Blizzard's guide [verified: Blizzard_ImplementationReadme.lua:42–43]. The category list draws subcategories only when the category is expanded [verified: Blizzard_CategoryList.lua; `Init` shows the toggle when `HasSubcategories`, `CreateSection` lists children only when `IsExpanded`]; `registerOptions` expands ours (`parent:SetExpanded(true)`). A client without subcategories registers the first page only. **No legacy `InterfaceOptions_AddCategory` branch** (it no longer exists; dead code is worse than none). `Compat.openOptions(page)` opens by numeric id (a name or the category object fails silently [verified: Blizzard_SettingsPanel.lua:282–291]) defaulting to, and falling back from an unregistered page to, the first. When the `Settings` API is absent, registration degrades to `nil`, load completes, and `/wfj config` prints "settings panel not available on this client".

### Key capture
`UI/KeyCapture.lua`: `KeyCapture.new(parent, { mode = "reveal" | "toggle", width, onKey, onRefused })`. Clicking the button starts a capture (refused while `InCombatLockdown()`) and relabels it **キーを押す** (Press a key; one language at a time). The capture buttons use the key-binding button art (`UIMenuButtonStretchTemplate`). **Handlers exist only while listening**: `start` sets `OnKeyDown` / `OnMouseDown` and `EnableKeyboard(true)`; `stop` clears `OnKeyDown`, puts back the template's own `OnMouseDown` (its pressed look, also called while listening) and calls `EnableKeyboard(false)`, Blizzard's `KeybindListener:SetListening` pattern [verified: Blizzard_Keybindings.lua:26–40]. A frame with an `OnKeyDown` script takes keyboard input whenever it is visible: standing handlers on the pages would swallow Escape, and the game menu would not open. One capture listens at a time (`KeyCapture.active`; starting one stops the other). Input is converted with `GetConvertedKeyOrButton` [verified: BindingUtil.lua:66]. Escape, a second click or `OnHide` (hooked; leaving the page) cancel; `BUTTON1` / `BUTTON2` are ignored so the starting click cannot bind itself.
- **reveal** (idle label **変更** / Change): the key goes through `Modifier.normalize` with modifier state ignored: a lone `LALT` completes as `lalt`, `Q` as `Q`, `Button4` as `BUTTON4`; the result is `Settings.set("modifier", …)`, applied immediately even when the key has an action (the warning line names it).
- **toggle** (idle label **キーを設定** / Set key): meta keys alone keep the capture waiting; the key completes as `CreateKeyChordStringUsingMetaKeyState(key)` [verified: BindingUtil.lua:116], so `CTRL-J` is allowed. A key equal to the modifier is refused (`<key> is already the key for showing English.`). A key with another action waits for **Replace** (`<key> is used for “<action>”. Replace it?`); a free key is written at once. Replace re-checks the modifier (`Options.unbindOrReplace`): if the modifier moved onto the pending key meanwhile, it writes nothing and shows the refusal. On refresh, a toggle key equal to the modifier's key (bound later in Key Bindings) shows `<key> is already the key for showing English.` `KeyCapture.setToggle(key)`: `SetBinding(old)` for each current `WFJ_TOGGLE` key, `SetBinding(key, "WFJ_TOGGLE")`, `SaveBindings(GetCurrentBindingSet())`: a real saved binding, the same as Blizzard's Key Bindings UI; when `SetBinding` refuses the new key, the old keys are put back and nothing is saved (→ false). **Unbind** (`clearToggle`) clears every current key and saves. Both refuse in combat.
- **Conflicts**: `KeyCapture.conflict(key, ours)` = `GetBindingAction(key)` when non-empty and not `ours`, shown as `GetBindingText(action, "BINDING_NAME_")`. `GetBindingAction` without `checkOverride` reads the saved binding, so a key the addon took over still names its own action [likely: the client only ever passes nil there, Blizzard_Keybindings.lua:127; checklist 14c (In-game checklists, first list)].

### Entry points
- **Esc → Options → AddOns → WoW Forever Japanese**, with *English Collector* and *About & Help* under it (listed expanded; the category list switches between them).
- **AddOn List button** (`UI/AddonListButton.lua`): `hooksecurefunc("AddonList_InitAddon", …)`; the list's element factory looks the global up on every call, so the post-hook sees every row [verified: AddonList.lua:258–261]. Rows are pooled; the hook creates one **設定** / Settings button (110 × 22; one language at a time) per entry the first time, anchored `LEFT` to `entry.Title` `RIGHT` +70 (the hidden Load AddOn button's slot [verified: AddonList.xml:82–85]), shown only when `C_AddOns.GetAddOnName(treeNode:GetData().addonIndex) == WFJ.ADDON` and hidden on other rows. While `AddonList_HasAnyChanged()` the button is disabled (should opening the settings close the list, unsaved enable / disable changes would be reset [verified: AddonList.lua:660–669]) and hovering it shows a one-language tooltip (`warn.addonChanges`: Apply or cancel your AddOn changes first., own `GameTooltipTemplate` frame `WFJSettingsTooltip`, parented to `UIParent` because the list's ScrollBox clips its children [verified: ScrollBox.xml:20]). A click only calls `Compat.openOptions()`: the addon never calls `HideUIPanel` (a protected call the addon never makes); the Settings panel manages the panels. `decorate` runs under `pcall` inside the list's row initializer, so a failure never breaks the AddOn List (the error is kept in `AddonListButton.error`). Installed only when the settings pages registered (`Compat.optionsCategories`), at load when `AddonList_InitAddon` exists; otherwise Main keeps `ADDON_LOADED` registered and installs on `Blizzard_AddOnList`. Absent at character select, where addons are not loaded.
- **`/wfj config [collector | about]`** (below).
- **TOC**: `## Notes: … Hold Alt (changeable) for the game's English. Settings: Esc > Options > AddOns, or /wfj config.` and `## IconTexture: Interface\AddOns\WoWForeverJapanese\Media\icon`: the addon's own 字 medallion (`Media/icon.tga`, 64×64, 32-bit uncompressed, bottom-left origin; drawn from the bundled IPA font), shared with the minimap button.

### Slash and keybindings
- **Slash** `/wfj`, `/wowforeverjapanese` (`UI/Slash.lua`), generic over the registry:
  ```
  /wfj                          status: `translation on · hold Left Alt for English · modifier up` (the modifier's display name), then one line per non-hidden setting, then `  togglekey = <key text> | not set` (a binding, not a setting); the footer lists `readings|glosses [on|off]` and `togglekey [<key>|none]`
  /wfj on | off | toggle        the master switch (sugar for `enabled`)
  /wfj <setting> [<value>]      read or set any setting by id, matched case-insensitively (/wfj modifier ctrl · /wfj modifier lalt · button4 · q)
  /wfj <group> <name> <value>   dotted ids may be split (/wfj area quests off · /wfj marker stale off)
  /wfj config [collector|about] open the settings (the main page, or a subpage)
  /wfj fix                      open the fix window (report a line); `the fix window is not available on this client` when it cannot open
  /wfj glosses [on | off]       sets `readings.glosses` when a value is given, then prints `glosses on|off · N meanings loaded` (N = `Data.count("gloss")`, the distinct meanings loaded). The setting also has its Options row and a line in `/wfj`'s status
  /wfj readings [on | off]      sets `readings.enabled` when the value is a boolean word, then prints `readings on|off`; any other second word falls through to the registry grammar (`/wfj readings glosses off` still sets `readings.glosses`); a word that matches neither prints `readings: expected on|off`
  /wfj togglekey [<key> | none] the settings page's toggle-key row by slash. Bare prints `togglekey = <key text>` or `not set`; `none` unbinds (`KeyCapture.clearToggle`); a key is parsed case-insensitively by `KeyCapture.parseChord` into the client's chord form, meta prefixes in `CreateKeyChordStringUsingMetaKeyState` order ALT CTRL SHIFT META (`shift-ctrl-q` → `CTRL-SHIFT-Q`; the minus key as `-` or `ctrl--`) and bound through `KeyCapture.setToggle`. The key must be one the page can capture and the client names (Forever GlobalStrings `KEY_*`): one printed character, F1–F24, a named key (SPACE, TAB, ENTER, PAGEUP, …), a NUMPAD key, BUTTON3–31, never the mouse wheel or a gamepad button. Refused with a reason, nothing written: a malformed chord (`ctrl-`, `-j`, `ctrl-ctrl-j`, `lctrl-j`, `foo-j`), `+` between parts (`ctrl+j` → "use - between keys"), a made-up key name (`foo`, `f25`), a lone meta key, BUTTON1 / BUTTON2 / ESCAPE / UNKNOWN, a second word (`ctrl j`), the modifier's key, any change in combat, and any change when the client cannot report combat (`key bindings are not available on this client`). `none` that leaves a key bound prints `<key> was not unbound`; a bind the client refuses prints `<key> was not bound`. A key bound to another action prints `<key> is used for "<action>"; type the same command again within 5 seconds to replace it`; the same command within 5 s binds it (the page's Replace)
  /wfj collector [status]       `WFJ: collector on · 12 entries (3 unsent) · 3.4 KB of 4.0 MB[ · full][ · paused (file from a newer version)][ · N errors]`
  /wfj collector on | off       sugar for `collector.enabled`
  /wfj collector path           the SavedVariables path (`Collector.path()`: `_classic_beta_` on a beta client, else `<client folder>`; `<ACCOUNT>` literal), "saved when you log out or /reload", counts, and that `/wfj collector send` sends them
  /wfj collector send [all]     opens the send window with the lines not sent yet; `all` packs every line again
  /wfj collector clear          first prints `type /wfj collector clear again within 5 seconds to clear N entries`; the same command within 5 s empties the dump (keeps the disclosure flag) and prints the count (the page's two-click Clear). An empty dump, or one from a newer version (never cleared, prints `not cleared`), skips the ask
  /wfj debug                    unresolved Compat candidates, state dump, `font failures: N (M pending)[ · <surface> ×n (<key> size=<size> flags="<flags>") · …]` (N = refused `SetFont` calls this session, M = records still waiting for the retry, then per surface by count, each with its first failing record's arguments), `readings: N quests / greetings loaded · on|off · N attached · N spans refused[ (first: <kind> <id> <first>..<right>: <why>)] · N errors` (quests and gossip greetings with readings, the setting, attaches this session, spans the guard refused, errors caught from the reading box; [Readings](readings.md)), `glosses: N meanings loaded · on|off` (distinct meanings loaded, and `readings.glosses`), `placeholders: N unknown tokens seen` (distinct unknown `{word}` tokens met this session, listed after the count when N > 0; `Placeholders.unknownTokens()`), memory, data counts (quests · items · spells · gossip · ui), the `ui:` index summary, `collector:` line, `modifier: <value> (<class>[ · override applied|queued|none])` (the override part only for a `bound` key), `addon list button: installed|absent`, settings build error
  /wfj debug fonts              the refused-font retry: `fonts: retry running|stopped · N tries · N left at the last try · Ns since PLAYER_ENTERING_WORLD · timer yes|missing` (or `fonts: no retry started (PLAYER_ENTERING_WORLD not seen)`), one pending record `fonts: pending <surface>.<key> now <path> <size> "<flags>" · visible true|false`, then a retry now: `fonts: records pending N → N after a retry now · own widgets pending N`

  /wfj debug quest <id>         the shipped row: one line per field (status word, h1, the first 60 chars of the Japanese) or `-`; `not shipped` when the id has no row
  /wfj debug item <id>          same, for the item description

  /wfj debug ui scan            English still showing on visible frames (up to 25): `hook?` = the dictionary knows it, `key?` = it does not
  /wfj debug objective          the objective index: `objectives: shipped N (objective N · area N) · indexed N · ambiguous N`, or `objectives: not built`
  ```

- **Keybindings**: `Bindings.xml` (auto-loaded, not in the TOC) declares two bindings, each calling a **global** function defined in `Main.lua`; a binding body runs as a global chunk and cannot see the `WFJ` namespace:
  - `WFJ_TOGGLE` (header `WFJ`) → `WFJ_ToggleTranslation()`: flips `enabled` and prints the new state. Its key is the player's own saved binding, set in Blizzard's Key Bindings, from the settings page, or with `/wfj togglekey`.
  - `WFJ_REVEAL` (`runOnUp="true" hidden="true"`) → `WFJ_RevealKey(keystate)` [verified: `runOnUp` + `keystate`, Bindings_Vanilla.xml:11–17 MOVEFORWARD; `hidden` used at :1320]. Never saved to a key: only the session override binding for a `bound` modifier uses it.
  - `BINDING_HEADER_WFJ`, `BINDING_NAME_WFJ_TOGGLE` and `BINDING_NAME_WFJ_REVEAL` (`Hold to show English (set in WoW Forever Japanese settings)`, so the entry explains itself if a client lists it despite `hidden` [likely hidden; checklist 14b (In-game checklists, first list)]) are Lua globals set in `Const.lua`.
  - The modifier is a binding only for the `bound` class, and only as a session override: `either` / `side` keys stay polled, and for `bound` keys the binding edge is an invalidation signal while the poll is the truth (above; [ADR-018](../adr/018-reveal-key-override-binding.md)).

## Invariants
- Defaults exist only in `define`. Account-wide only (no per-character profiles) in v1.
- A settings-schema change needs a migration and a test. The `key` kind needed no schema bump: every older stored value (`alt` / `ctrl` / `shift`) normalizes to itself, and `WFJ_DB` stays schema 1.
- The player's saved bindings are written only by an explicit toggle-key action on the settings page (Set key, Replace, Unbind) or `/wfj togglekey` (the same refusals and a typed-again Replace); the modifier never writes them.
- The modifier and the toggle key never share a key (refused in both directions; Replace re-checks at click time).
- A settings frame has `OnKeyDown` / keyboard input only while its capture is listening, and at most one capture listens.

## Edge cases
- `alt` matches `LALT` and `RALT` (etc.); `lalt` matches only the left key. Changing the modifier while held → `State.modifierHeld=false`, fire (the binding edge is cleared too).
- Downgrade to a build without the `key` kind: a stored `lalt` / `Q` / `BUTTON4` fails its `choice` coerce and the old build falls back to Alt; `WFJ_DB` needs no reset. A toggle key set from the page is an ordinary `WFJ_TOGGLE` binding and keeps working.
- Override bindings are session-only [likely: their documented purpose; checklist 14c (In-game checklists, first list)]: disabling the addon and `/reload` gives a taken-over key its action back, and nothing stays bound.
- Typing a `bound` key in an EditBox reveals nothing (the binding does not fire while an EditBox has focus).
- A lost key-up (the window lost focus mid-hold) is cleared by the watcher's poll, so English does not stay on.
- A `bound` modifier set by slash in combat is queued and applied once on `PLAYER_REGEN_ENABLED` (a polled key applies at once); the page refuses modifier changes in combat (dropdown and captures disabled), and a capture open when combat starts is cancelled.
- Escape and chat typing are never taken by the pages: no key handler exists outside an active capture, and pages stay hidden until the Settings panel shows them.
- The player later binds the `bound` modifier key to something in Blizzard's UI: the priority override still wins while loaded; the page shows the takeover warning on its next show. A toggle key rebound elsewhere shows live on the next show (`GetBindingKey`).
- Modifier equal to the toggle key: `Settings.set` refuses it (slash and page); a toggle capture equal to the modifier is refused on the page. Only an exact key conflicts (`J` and `CTRL-J` coexist).
