# Client limits

> What the World of Warcraft: Forever client keeps from addons, what that means for the addon, and where each fact comes from. The client marks some values **secret**: an addon may hold one, pass it on and put it on the screen, but may not read, compare, concatenate or index with it (`issecretvalue` tells one apart; `type()` still answers). Every claim here cites the client's own files, read from the 1.60.1.70170 extract (`blizzard_apidocumentationgenerated`), or an in-game trace (`/wfj debug tooltip`).

| Limit | What the client hides | What the addon does | Source |
|---|---|---|---|
| **Buff and debuff tooltips in combat** | The aura's instance id, spell id, icon and every tooltip row. `C_UnitAuras.GetAuraDataByAuraInstanceID` and `GetAuraDuration` take no secret argument from an addon (`SecretArguments = "AllowedWhenUntainted"`), so a hidden id cannot be resolved. Blizzard flags individual spells "never secret"; those keep working. | Leaves the client's English, keeps nothing between passes, renders again the moment the rows are readable. No addon can identify the buff, so nothing is guessed. | `secretpredicatesdocumentation.lua` (`SecretWhenUnitAuraRestricted`), `unitauradocumentation.lua:190–212, 286–290`; trace 2026-10-02: `SetUnitAuraByAuraInstanceID(player, <secret>, nil)`, three secret rows |

## Rules these limits set

- A hidden value is never compared, concatenated, measured or used as a key. A FontString whose text is secret is never read back; a record that would compare it is let go first (`Render.discard`).
- Nothing is learnt or remembered to work around a limit. A surface the client hides is left in the client's English until the client shows it, and shows Japanese again on its own then.
- A new limit, or one that lifts (the client's rules move between builds), is found by the trace: `/wfj debug tooltip on`, the hover, `/wfj debug tooltip`. The entry of a hidden pass names every data row, the row map and the duration object.
