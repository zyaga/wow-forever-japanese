# ADR-008: Generated data layout: id-range shards, a TOC-managed generated block, positional slots

- **Status:** Accepted
- **Date:** 2026-09-13

## Context
`data/` is the source of truth (ADR-001, ADR-006); the client needs Lua tables. The generated files must be a build artifact CI can regenerate and diff, must key every row by game id ([principle 5](../architecture/principles.md#5-every-translation-is-keyed-by-the-game)), must not carry English translation data (ADR-002; the one exception is below), and must stay diff-friendly in data PRs that touch a handful of ids. The addon cannot load files dynamically: every file is listed in the TOC or in an XML include.

## Decision
- **Row shape:** `WFJ.Data.add("<type>", { [id] = { <field slots…>, <h1 slots…>, "<status chars>" } })`. Slots within a row are fixed by a hand-written slot map in `Core/Const.lua` and `emit/schema.py` (parity-tested); the id is the table key, never a position. Quests: 5 field slots, 5 h1 slots (the first 32 bits of each field's English hash), one status string (`.` trusted · `s` stale · `u` unaligned · `m` not shipped). Items/spells: `{ description, h1, status }`. Gossip: `["<16 hex key>"] = { text, status }`.
- **Sharding:** one file per 1,000-id range (`Quest_0007.lua` = ids 7000–7999), mirroring the JSONL shards, empty ranges omitted. A data PR touches the same shard in `data/` and `Data/`.
- **File list:** the TOC carries a generated block between `# <<< generated by wfj generate. Do not edit between the markers; wfj validate diffs this block.` and `# >>>`, rewritten by `wfj generate` (Meta, Vectors, then shards by type and range). Everything else in the TOC is hand-maintained; `wfj validate` diffs the block. The markers are `#` lines, which the TOC format defines as comments (`##` directives are the special case) [long-standing TOC format; the busted loader and `toc-check` skip them the same way].
- **Shipped extras:** `Data/Meta.lua` (content-derived facts only: schema, English source versions, counts, field lists; no timestamp) and `Data/Vectors.lua` (the hash vectors, so `/wfj debug hash` self-checks on any client).
- **The one exception to [principle 4](../architecture/principles.md#4-the-addon-never-ships-stored-english):** `Data/Vectors.lua` is the only English in the addon. It holds the 50 synthetic hash-vector sentences (markup, placeholders, whitespace cases; not game text), it is never rendered, and it exists so the hash primitive can be proven on the live client's Lua. ADR-002 governs displayed text; translation data ships Japanese and hash prefixes only.
- **Strings:** Lua double-quoted literals; backslash, quote, newline, CR, tab escaped, other control characters as `\ddd`, UTF-8 verbatim. `luac` parses every generated file in CI.

## Consequences
- Regenerate-and-diff is exact; hand edits fail CI (`wfj validate`).
- Many small files instead of a few large ones: negligible load cost, stable diffs.
- The TOC is partly generated; contributors edit only outside the markers.
- Memory is measured in-game, not modelled ([Testing → checklist 9](../testing/strategy.md)); LoadOnDemand and compression stay available as later levers without a format change.
- A data-format change is a `schema` bump in `Meta.lua` and `WFJ.SCHEMA` together plus a regeneration; the only reader is `Core/Lookup.lua`, by design.

## Alternatives considered
- **`Data\Data.xml` `<Script file=…>` include**: keeps the TOC untouched but assumes XML-include behaviour on the Forever client and makes the busted loader an XML reader; rejected for one fewer unverified assumption.
- **1,000 *entries* per file**: smaller file count, but adding one id shifts every later file: unreviewable diffs.
- **One table per field** (`Data.quest.title[id]`): simpler reads, several times the table overhead, and splits one entry's fields across files.
- **A separate hash table per type** instead of inline h1 slots: one more table per row to keep in step; the inline prefix is enough for stale display and the collector's changed-detection.
