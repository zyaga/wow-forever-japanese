# ADR-013: The collector records only unknown English, normalized for privacy, and its import never overwrites a curated source

- **Status:** Accepted. Implemented in `Core/Collector.lua`, the surfaces' record calls, `UI/Slash.lua`, `pipeline/wfj/io/collector_dump.py`, `pipeline/wfj/cmd/import_.py`, `pipeline/wfj/cmd/check.py` (`UNCONSULTED_SOURCES`) and `.github/ISSUE_TEMPLATE/collector-dump.yml`.
- **Date:** 2026-09-14
- **Amended by:** [ADR-053](053-forever-shown-english-is-the-english.md), decision 3. The import now replaces a stand-in line (VMaNGOS, pfQuest, an older client) with the English the Forever client showed, keeps the same client's own tables and quest cache, and `check` consults collector English for quest and gossip.

## Context
Quest progress/completion text, Forever-new quests, rendered item/spell descriptions and NPC names exist only in players' clients. The addon ships no English (ADR-002), only the first 32 bits of each field's English hash (`h1`, ADR-008). The Forever beta is the moment to harvest this text. Players will post the file publicly on GitHub, so it must be private by construction, and the repo's English store must not be damaged by a bad, old or divergent dump. `data/english/` already holds curated English from pfQuest (quests) and wago (item/spell names), and an importer that rewrites a whole type would delete any other source's lines.

## Decision
1. **Record only what the addon cannot recognise.** A field is known when its shipped `h1` equals the first 32 bits of `Hash.key(Normalize.v1(e))` of the live English; everything else (unknown, changed, never shipped) is recorded once per `(kind, id, field)` and hash, into `WFJ_Collector`, its own SavedVariables, separate from `WFJ_DB`. Kinds: `quest` (title/objectives/description/progress/completion), `item` / `spell` (`description`), `npc` (`name`, the quest giver). A stored key with another hash is replaced.
2. **Privacy by normalization, in Blizzard's tokens.** The stored text is `normalize_v1` of the whole text with markup stripped first (a break inside a link label never splits the link), split into paragraphs and written in Blizzard's own tokens, the pfQuest convention ([ADR-011](011-provenance-layers-and-completeness.md)): the player's name as `$N`, paragraphs joined with `$B$B`, and, for quests only (the only text carrying `$C`/`$R`), class and race as `$C`/`$R`. That includes the lowercase forms Blizzard prints for `$c`/`$r` ("young druid", quest 456), which `normalize_v1`'s exact-case replacement would leave in place. `Normalize.v1` of the stored text equals `Normalize.v1(raw, player)` except that a lowercase class/race word also becomes a token. Refused: text naming the player's bind location (`SKIP`: the Hearthstone item, the Hearthstone and Astral Recall spells); our own output (any CJK character, or a marker message anywhere); item, spell and NPC text containing the player's name as a whole word (Blizzard never writes the name there, so a match is a coincidence and a placeholder would point at the name); in quest text, a player name `normalize_v1` cannot replace (< 3 code points) present as a word; and any record while the player name or the client build is unknown. The name checks run on the markup-free text. No GUID, time, realm, zone, character or account field exists in the shape; NPCs are keyed by the creature id cut from a `Creature`/`Vehicle` GUID at record time. The disclosure flag lives in `WFJ_Collector.disclosed`. Class/race → `$C`/`$R` in quests is right for the common `$C`/`$R` lines; a literal class or race word (~1.8% of curated quest lines) is the known exception, visible in an audit when dumps from different classes disagree.
3. **Additive import, not yet consulted.** `wfj import english collector` re-validates every entry (hash recomputed from the text, tokens limited to `$N`/`$C`/`$R`/`$B` and no `{…}` placeholder, no kana or kanji, a known build) and, per `(type, id, field)`, adds English where none exists, replaces only earlier `collector@` lines, and reports (never applies) disagreements with pfQuest or wago lines. The curated importers in turn do a **source-owned merge**: they replace their own lines and any `(id, field)` they provide and keep other sources' lines. `check`, `validate` and `stats` ignore `collector@` English when building scopes (`UNCONSULTED_SOURCES = ("collector",)`) until a re-check policy is decided.
4. **A constant cap.** `Collector.CAP_BYTES` = 4 MiB against a per-entry estimate of the SavedVariables text (`2·#key + #e + escapes + 117`, measured on the fixture), one message per session, cleared by the next successful write; no `collector.capMB` setting and no `number` settings kind. The same raw text for the same key answers from a per-session memo (no re-hash); `capped` and the state-dependent refusals are not replayed.

## Consequences
- Positive: a dump is safe to post publicly; hashes agree across Lua and Python (all 50 hash vectors + the committed SavedVariables round-trip fixture); a bad or divergent dump cannot erase curated English; re-importing the same dump is a byte no-op; a collector error is counted and never breaks a surface.
- Negative: text the repo already has English for but the addon does not ship an own-field hash for (quest progress/completion, item/spell descriptions today) is recorded anyway, since the addon cannot know; spells without a non-empty `GetSpellDescription` record nothing; a disagreement with pfQuest needs a person to decide; the cap and the per-entry estimate are guesses until real dumps exist; wording the client resolves by the character's gender (`$G`) is kept as shown (not identifying; stated in the disclosure and the issue form); a player name of three or more letters that is also a common word ("Light") becomes `$N` in quest text, visible in an audit when dumps disagree.
- Notable: importing a dump changes nothing `check` / `validate` / `stats` see (no hash, since quest `progress`/`completion` keep the `description` fallback; no scope, number check or Vanilla id), so a dump is safe to import and commit (`test_check_and_validate_ignore_collector_english`). The cost is that collector English earns nothing yet. A re-check policy, still open, will decide how collector English may change hashes, scopes, number checks and Vanilla ids.
- **Gossip:** a `gossip` kind, `recordGossip(raw, guid)`, keyed by the gossip key, with the speakers' creature ids in `n` and the quest token rules (`$C`/`$R`); the import unions `npcs`. `wfj stats` lists collector gossip English by NPC count; that listing builds no scope and changes no yield, so decision 3's "stored, not consulted" stands ([ADR-017](017-gossip-surface.md)).
- The SavedVariables path and string escaping, `UnitGUID("questnpc")` and the need for the Astral Recall / Hearthstone spell skip are [likely]; in-game checklist 8 imports a real dump to confirm, and the reader already accepts positional or keyed arrays and Lua string escapes.

## Alternatives considered
- **Store raw English, strip personal data on import**: the file would carry the player's name until import, in a public issue; rejected.
- **Our own `{name}`/`{class}`/`{race}` placeholders and `\n` paragraphs**: a second convention beside pfQuest's `$N`/`$C`/`$R`/`$B`, so `count_english` would count collector paragraphs differently from pfQuest's.
- **Substitute `$N` for the name in item/spell/NPC text too**: Blizzard never writes the name there; a match ("Guard", "Light") is a coincidence and the placeholder would point at the name; refused instead.
- **Fully normalized text (no paragraph breaks)**: loses the paragraph structure the completeness rule (ADR-011) needs.
- **Collector English overwrites pfQuest when it differs**: the beta client's text may be a transient or per-player variant; a person decides.
- **Substitute class and race in every kind**: item/spell/NPC text has no `$C`/`$R`, so "Hunter" there is an ordinary word; replacing it would corrupt the English.
- **A configurable cap (`collector.capMB`)**: nobody configures it and it would need a new settings kind; revisit when real dumps exist.
- **Keep whole-type rewrites in the curated importers**: the first `make import-english` after a collector import would silently delete collector lines.
