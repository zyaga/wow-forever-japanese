# ADR-055: forever-vo's player captures as an English source

- **Status:** Accepted
- **Date:** 2026-10-03
- **Related:** [ADR-019](019-quest-english-per-field-and-live-check.md) (quest English per field, VMaNGOS) · [ADR-053](053-forever-shown-english-is-the-english.md) (collector English outranks stand-ins)

## Context

A quest's progress and turn-in text exist only in what the server sends at the NPC: no client table and no quest
cache holds them. Our offline source for that text is the VMaNGOS world database, a vanilla server, so the quests
Forever added (ids from 90000 up) have no progress or turn-in English at all. About 758 of them were in that state,
and a player saw English with the "not translated" marker at every one of those NPCs.

The addon's own collector records the text as the maintainer plays, but that covers only quests one person has
reached. Before deciding, the maintainer asked for every project that might hold the text. What was checked:

| Source | Progress / turn-in text for Forever's new quests |
|---|---|
| VMaNGOS, our snapshot and the newest one | none: its quests stop at vanilla ids |
| The Forever client's tables and quest cache | none: the server sends this text only at the NPC |
| Questie's Forever data, the pfQuest Forever update, ForeverDB, quest guide sites | ids, givers, objectives and rewards only |
| QuestieTrace, SpeakStone | collect the text, but submissions go privately to those projects |
| forever-vo (github.com/quinn-dougherty/forever-vo) | **yes**, public, MIT licensed |

forever-vo is a voice-over addon. Its players save the quest text they see, export it with `/fvo export`, and paste
it into a GitHub issue; a workflow in that repository adds each submission under `captures/`. At commit `025070f` it
held 577 submissions with about 27,000 quest lines from builds 69913 to 70205.

## Decision

1. **forever-vo is an allowed English source** for quest progress and turn-in text and NPC greetings (the gossip
   window's text) (the maintainer's approval, recorded in the project's rules). It is read from a clone pinned by commit (`FOREVER_VO`, `FOREVER_VO_SHA` in the
   Makefile) by `wfj import english forever-vo` (`run_forever_vo` in `pipeline/wfj/cmd/import_english.py`, reader
   `pipeline/wfj/io/forever_vo.py`). Lines carry `src: forever-vo@<commit>`.
2. **Only English clients.** The captures name no client language, and some come from German clients. An entry
   counts only when its quest title equals the English title we hold for that quest id.
3. **Two submissions must agree.** A text is taken only when at least two separate submissions sent it (compared
   normalized). When submissions disagree, the text sent by the most wins; a tie goes to the text that keeps a
   player token (`$N`, `$C`, `$R`), then to the newest build.
4. **It fills gaps only.** A (quest, field) another source already holds is left alone. Where VMaNGOS has the line,
   a capture differs mostly in form (`$B` written out, one gender's word for a `$g` choice), and replacing it would
   mark a hand-written translation stale for nothing. Our own collector outranks forever-vo, and VMaNGOS never
   replaces a forever-vo line.
5. **NPC greetings** carry no quest title, so the language is told per submission: a submission whose quest entries
   all match the English titles we hold (at least one) is an English client, and its greetings count. A greeting
   needs two such submissions, is keyed by the hash of its English like every gossip line, keeps the creature ids
   that said it as `npcs`, and is added only where no other source holds that key (`read_greetings`).
6. **Credit follows the data.** `ATTRIBUTION.md` (generated by `python -m wfj.dev.gen_attribution`) carries the
   forever-vo credit and its MIT notice exactly while some line in `data/english/` comes from it;
   `test_forever_vo_is_credited_exactly_while_its_lines_remain` fails when the two disagree.

## Consequences

- The first import adds 630 quest lines (220 progress, 410 turn-in) and 171 NPC greetings. It skips 383 texts only one submission sent, 70
  German entries and 75 fields where submissions disagreed but a majority decided. 636 more matched our existing
  English exactly, which is good evidence the captures are accurate.
- A text one player sent stays out until a second sends it; refreshing the pin picks those up.
- A capture written for one gender (`brother` / `sister`) ships that wording; a player of the other gender sees the
  stale marker until our collector records their version.
- **Removing the source** is a data change, not a code hunt: when a better source or our collector has replaced
  every `forever-vo@` line (`grep -c forever-vo@ data/english/quest/*.jsonl`), run the generator, which drops the
  credit; then remove the Makefile step, the importer and this source from the rules. The Japanese is unaffected:
  it translates Blizzard's text, not anything forever-vo wrote.

## Alternatives considered

- **Wait for the collector alone.** Coverage would follow one person's play; most new quests would stay English
  until launch and after.
- **Let forever-vo replace VMaNGOS where they differ.** Most differences are form, not wording, and each would mark
  an existing translation stale.
- **Take single submissions.** One mistaken or tampered submission would decide a line nobody else confirmed.
- **Wowhead's Forever pages.** Their terms forbid it as a data source.
