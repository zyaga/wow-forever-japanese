# ADR-022: Book and trainer-greeting surfaces: a book row keyed by its English hash, a SimpleHTML adapter, the trainer greeting under the NPC talk area

- **Status:** Proposed; accepted once in-game checklist 17 passes. Implemented in `UI/ItemText.lua`, `Core/Lookup.lua` (`Lookup.keyed`), `Core/Data.lua`, `Core/Const.lua` (`WFJ.AREAS` += `books`), `Core/Settings.lua` (`area.books`), `UI/Options.lua`, `UI/Slash.lua` (`/wfj debug book`), `Main.lua` (`keyOf`), the TOC; `pipeline/wfj/core/model.py`, `core/markup.py` (`html_mismatch`), `core/status.py` (`PROSE_KINDS`), `cmd/check.py`, `cmd/import_.py`, `cmd/generate.py`, `emit/schema.py` (`KEYED_TYPES`), `emit/lua_writer.py` (`keyed_rows` / `keyed_text`); `data/book/`.
- **Date:** 2026-09-15

> Amended by [ADR-034](034-forever-is-the-only-target.md): there is no trainer greeting kind (Forever has no trainer greeting), so decisions 1–4, 10 and 11 hold for books only. The book surface stands; `UI/ItemText.lua` hooks Forever's book writer.

## Context
The English of 1,257 book pages (`data/english/book`, keyed by the VMaNGOS `page_text` entry) and 24 trainer greetings (`data/english/trainer_greeting`, keyed by the hash of the English, as gossip, [ADR-005](005-gossip-key-fingerprint.md)) is imported ([ADR-019](019-quest-english-per-field-and-live-check.md)), but nothing could hold their Japanese and no screen showed it. Client facts [verified: `classic_era` UI source, 1.15.9]:

- **The item text window** (books, letters, plaques). `ItemTextFrame_OnEvent` is bound in XML by `function=`. On `ITEM_TEXT_BEGIN` it sets each HTML text type's font object (`P`, `H1`, `H2`, `H3` → `ItemTextFontNormal`) and colour; on `ITEM_TEXT_READY` it writes `ItemTextPageText:SetText("\n" .. ItemTextGetText())`, appending `"\n\n" .. ITEM_TEXT_FROM .. "\n" .. creator .. "\n"` when `ItemTextGetCreator()` returns one, then sizes the scroll child (`SetHeight(1)`, `UpdateScrollChildRect()`, `SetHeight(frame height + range + 30)` when `floor(range) > 0`). Every page turn fires `ITEM_TEXT_READY` again (`Blizzard_UIPanels_Game/Classic/ItemTextFrame.lua:20–128`, `ItemTextFrame.xml`).
- **`ItemTextPageText` is a SimpleHTML**, not a FontString: `SetText`, per-text-type `GetFont` / `SetFont` / `GetFontObject` / `SetFontObject` / `GetTextColor` / `SetTextColor`, and **no `GetText`** (`SimpleHTMLAPIDocumentation.lua`). `SurfaceState` records assume a FontString.
- **No page id is exposed.** The item text API gives the text, page number, item, creator and material, never the `page_text` entry. 63 English hashes are shared by more than one page ("Missing Text" and other identical pages in different books); 62 pages are HTML (`<HTML><BODY>…`); 173 carry `$B` / `$N` / `$C` tokens.
- **The trainer greeting.** `ClassTrainerFrame_Update` writes `ClassTrainerGreetingText:SetText(GetTrainerGreetingText())` (`Blizzard_TrainerUI.lua:162–164`), a 260×30 FontString; `UI/Trainer.lua` already post-hooks `ClassTrainerFrame_Update` for the row subtexts.

## Decision
1. **Two translation types, keyed in `data/` like their English.** `data/book/book-NNNN.jsonl` (id = the `page_text` entry, field `text`) and `data/trainer_greeting/trainer_greeting-NN.jsonl` (id = the 16-hex hash of the English), full translation line shape. `objective` stays English-only. `wfj import draft book|trainer_greeting` takes integer ids for `book`, 16-hex string ids for `trainer_greeting` (all `HASH_KEYED` types and `ui` take strings).
2. **Both are prose, checked against their own English.** `status.PROSE_KINDS = ("quest", "book", "trainer_greeting")`: names, numbers and completeness, as quest fields; a passing line is `trusted`, a line whose English hash changed since it was checked is `stale`. Books add an **HTML rule**, `markup.html_mismatch(en, ja)`: when the English is an HTML page (it starts with `<HTML`, case-insensitive; a plain page's bracketed prose such as `<illegible text>` is not markup), the Japanese must carry the same tag sequence (tag names compared case-insensitively, attributes whitespace-collapsed, `<BR/>` and `<BR></BR>` distinct), or the line is `rejected` `markup_changed:html:<first difference>`. The SimpleHTML renders those tags; a dropped or reordered tag shows broken markup.
3. **A book row's Lua key is `english.hash`, not the page id.** The client exposes no page id, so the addon finds a page by its live English, as gossip ([ADR-005](005-gossip-key-fingerprint.md)): `Data/Book/Book_<2 hex>.lua`, rows `[english.hash] = { text, "." }`. The status is always `.`: a key match means the client shows exactly the English the Japanese was checked against, so no stale marker applies (the reasoning of the quest live check, [ADR-019](019-quest-english-per-field-and-live-check.md)); a page whose English changed has a different key and shows its live English. Pages sharing one English with equal Japanese generate one row. "Equal" compares whitespace runs as one space, as `wfj import` compares texts, and `lua_writer.keyed_rows` writes the lowest page id's text for that key. With truly different Japanese, `generate` (and so `validate`) raises naming the page ids: one English, one Japanese, never resolved silently ([principle 5](../architecture/principles.md#5-every-translation-is-keyed-by-the-game)). The one stated exception: a `stale` page whose checked English equals a current (trusted) page's English gives way to that page, which was checked against it. Trainer greetings ship as gossip does: `Data/TrainerGreeting/TrainerGreeting_<2 hex>.lua`, `[id] = { text, status }`.
4. **One keyed reader and one key function.** `schema.KEYED_TYPES = ("gossip", "book", "trainer_greeting")` with one `lua_writer.keyed_rows` / `keyed_text`; `Lookup.keyed(type_, key) → { ja, status }` (`Lookup.gossip` delegates; `Lookup.get` routes the keyed kinds); `Main`'s `keyOf(type_)` returns a closure over `Collector.keys(text, player)` candidates (the first with a shipped row of that type, else the full key), used for every keyed type. Three keyed types is where one shared reader pays off. Gender alias rows and short-name candidates: [ADR-024](024-gender-variants-and-short-name-candidates.md).
5. **`UI/ItemText.lua` hooks the frame's `OnEvent`.** Surface `itemtext`, area `books`, kind `book`, record `page`. `ItemTextFrame:HookScript("OnEvent")` (an XML-bound script, [ADR-009](009-surfaces-post-hook-the-writer.md)'s frame-script exception) runs after the client's handler; `HookScript("OnHide")` releases. A `hooksecurefunc(ItemTextPageText, "SetText")` post-hook tracks the text the SimpleHTML last received. `ITEM_TEXT_BEGIN` snapshots the client's per-type font objects, fonts and colours, then forgets the previous item's record. `ITEM_TEXT_READY` shows the page only when the SimpleHTML last received exactly `"\n" .. ItemTextGetText()` (the ADR-009 equality guard); a page turn is a new record on the same key, never the previous page's text. After each write the scroll child is re-measured the client's way (`refit`). `ItemTextTitleText` (a name) and `ItemTextCurrentPage` are `NEVER_TOUCH`.
6. **A local SimpleHTML adapter.** `ItemText.page` gives `SurfaceState` the FontString interface: `GetText` = the logical text; `SetText` writes the client's text as is and any other text as `"\n" .. text` (an inline marker on an HTML page becomes a `<P>` inside `<BODY>`); `SetFont(face)` applies the face to all four text types then puts back each type's colour. SimpleHTML's `SetFont` returns nothing, so a refusal is read back from `GetFont` and reported as `false` (the refused-font retry then covers it), after putting back the text types that took the face; `SetFont(original)` sets each type's captured font, then its font object, then its colour (right whether or not re-assigning the same font object re-applies it). It lives in `UI/ItemText.lua` only: there is one SimpleHTML consumer, so no generic widget abstraction.
7. **A player's letter is never touched.** A page with a creator is left exactly as the client wrote it (no write, no font, no marker), even when its text matches a row and `marker.missing` is on.
8. **Markers inline, no banner.** The stale / missing message sits above the prose inside the page.
9. **`area.books`** (boolean, default on, group `areas`, "Books & letters" / 本と手紙) gates the book window; no migration (the default lives in `define`).
10. **The trainer greeting is NPC talk.** `Trainer.showGreeting()` runs first in the existing `ClassTrainerFrame_Update` post-hook: area `gossip`, kind `trainer_greeting`, record `greeting` on surface `trainer`, keyed by `keyOf("trainer_greeting")` on the API English, shown only while the widget holds exactly `GetTrainerGreetingText()`; released with the surface on hide. `ClassTrainerGreetingText` stays on `NEVER_TOUCH`, which only the labels dictionary reads. `area.gossip`'s label becomes "NPC talk (talk window, trainer greeting)" / NPCの会話（会話ウィンドウ・トレーナーのあいさつ）.
11. **Book pages are machine-drafted in batches** ([ADR-023](023-server-only-text-drafted-in-measured-batches.md)). Useful in-game test pages: 637 and 638 (pages 1–2 of 12 of *The Kaldorei and the Well of Eternity*, Stormwind Keep's Royal Library), 287 (*Kurdran Wildhammer*, Valley of Heroes), 1031 (*Horatio Montgomery, M.D.*, Stormwind; HTML), 1762 (*The Armor of Mannoroth*, Orgrimmar; `$B` tokens), 1756 (*Pteradon Skeleton*, Ironforge Hall of Explorers).

## Consequences
- `Data/Meta.lua` counts the book type and pins its English source version (`vmangos`).
- A page with no shipped row, a page the client wrote differently from the getters, and every player letter are untouched live English.
- The data stays keyed by game id ([principle 5](../architecture/principles.md#5-every-translation-is-keyed-by-the-game)); only the generated Lua is keyed by the hash. A book page cannot show a stale marker in game: a stale line is either an exact key match (shown plain) or a miss (English).
- Drafts that give two identical pages different Japanese stop `generate` with the ids named, so batches group book rows by English hash and draft each key once. Pages sharing a key show one Japanese laid out for the first page: where their English breaks paragraphs differently (pages 156, 349, 1090, 1270, 2967), the others show the same text with the first page's paragraph breaks, and `cut --ids --redraft` of one such page re-drafts every page with its key.
- A book page's Japanese must keep the English's HTML tags in order; a translator cannot restructure a page.
- **[unverified, checklist 17]:** that the live `ItemTextGetText()` equals the VMaNGOS page text after normalization (if not, pages stay English; `/wfj debug book` shows the live keys); that `SetFont` / `SetFontObject` on a SimpleHTML text type keeps or resets its colour (the adapter re-applies colours either way); that a `|c` colour code renders inside a SimpleHTML `<P>` (the inline marker); that a two-line Japanese greeting fits the 260×30 box.
- **Rollback:** revert the PR and re-release. The types are additive; `WFJ_DB` gains only an optional `area.books`, which an older build ignores. No migration.

## Alternatives considered
- **Key `data/book` by the English hash**: matches the Lua key, but gives up the game id the data rule requires and merges pages that are distinct in the game; the hash is derivable at generate time from `english.hash`.
- **A stale marker on book pages** (ship `s` for a stale line): a key match proves the English is exactly what was checked; the marker would claim a change that did not happen, and a changed English never matches.
- **Keep the creator block after the Japanese** (translate a matching letter and re-append "From \<player>"): the missing marker would then mark every player letter, which can never be translated. Player letters are left alone.
- **A marker banner on the book window** (as the quest and gossip windows, [ADR-017](017-gossip-surface.md)): the page already sits in a scroll frame with its own title; inline markers suffice and add no frame.
- **`hooksecurefunc("ItemTextFrame_OnEvent")`**: `[likely]` the XML `function=` binding holds the function value, so a by-name post-hook would not run (the same unverified premise as [ADR-009](009-surfaces-post-hook-the-writer.md)); `HookScript` is correct under either binding semantics.
- **A generic "hashed surface" module or a widget adapter in `SurfaceState`**: one SimpleHTML consumer; the adapter stays local until a second appears.
- **The trainer greeting under a new area**: it is NPC prose like the talk window; a separate switch adds a setting no one asked for.
