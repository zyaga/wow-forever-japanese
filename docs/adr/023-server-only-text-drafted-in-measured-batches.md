# ADR-023: Server-only text drafted in measured batches: cut, lint, expand; style version in the draft name; held-back lines through reject rulings

- **Status:** Accepted. Implemented in `pipeline/wfj/dev/translate_batch.py` (`cut`, `expand`), `dev/objective_items.py`, `dev/translate_lint.py` (with `dev/lint_names.py`, `dev/glossary.py`), `dev/rule_held_back.py`, `core/style.py`, `core/status.py` (`_rank`: style version), `core/decisions.py` (`hand_written_all_rejected`), `cmd/validate.py` (rule 2), `pipeline/translation_glossary.tsv`, `pipeline/translation_not_names.tsv`, `docs/content/translation-style-guide.md`. Runbook: [Translation batches](../operations/translation-batches.md).
- **Date:** 2026-09-16

> Amended by [ADR-034](034-forever-is-the-only-target.md): there is no trainer greeting kind (Forever has no trainer greeting), so there is no `--kind trainer_greeting` batch.

## Context
Quest progress text, quest completion (turn-in) text, NPC gossip and book pages come only from the server: the client can never give us their English, so their Japanese has to be written from the Vanilla English (VMaNGOS, ADR-019). Most of it had no Japanese at all.

[ADR-014](014-machine-drafted-text-and-ui-dictionary.md) already gave machine text a path into `data/` (`wfj import draft`, machine provenance with its model, hand-written always wins). It had no way to cut a batch, check a draft before import, or record which prompt wrote a line. Drafting runs in small measured batches, so each batch's size is known before it is drafted.

Some lines are a special case: they carry hand-written Japanese that ships nothing, because every hand-written variant on them fails the rules (`truncated`, `alignment_failed`, `duplicate_conflict`, `numbers_changed`, `not_japanese`), so the addon shows the live English. Machine output may not replace a human translation without an explicit, logged decision ([principle 6](../architecture/principles.md#6-provenance-on-every-line-people-over-machines)).

## Decision
1. **The pipeline calls no model.** A batch is deterministic tooling around one drafting step: `translate_batch cut` → the drafting model writes `{ref, ja}` rows → `translate_lint` → `translate_batch expand` → `make import-draft` → `make check` / `generate` / `validate`. Each drafting step runs in its own fresh context, so the Japanese is never read in bulk by the process that runs the batch. The prompt text lives in the runbook, the rules in the style guide and glossary, all versioned in git, not in code.
2. **`cut` selects, groups and maps.**
   - **Selects** lines of the kind's field that have English and no `trusted` line, no machine draft yet, and **no hand-written (`human` / `correction`) variant**: a draft beside one could not ship without a ruling (ADR-014 §3). A bare label (no lower-case word, no token, no sentence punctuation: `Stratholme`, `Cooking`) is skipped and ships as the English, except in a title-case kind (`TITLE_CASE_KINDS`: `quest_title`, `objective`), where title case capitalises every word and real titles ("Blackrock Menace") would otherwise never be drafted. A title that is only a name (a person, place, item or spell) ships that name in English letters. Every field of a quest whose English title matches `io/wdb.PLACEHOLDER_TITLE` (`<UNUSED>`, `<NYI> <TXT> …`, `REUSE`) is dropped: nothing there is meant for a player.
   - **Groups by unique English** after the token mapping: one row per text, listing every `(id, field)` it fans out to, so each text is drafted once and identical English cannot get different Japanese. Book rows group by the English hash, the addon's key for a page, so pages whose English differs only in whitespace share one row. Same store → byte-identical batch.
   - **Maps tokens** to the addon's form before the model sees them: `$N`/`$n` → `{name}`, `$C`/`$c` → `{class}`, `$R`/`$r` → `{race}`, a `$B` run → a paragraph break. `$G<male>:<female>;` stays literal: the style guide asks for one gender-neutral wording, because the addon cannot expand a Japanese pair. Server counters (`$1997w`) are kept exactly. An HTML book page's English reaches the row with its tags and line breaks unchanged.
   - **Objective items**: quest rows carry `items`, the item names found in that quest's English objectives, so the drafter can tell a lower-case item name (kept in English letters) from an everyday word (translated).
   - **Kinds**: quest `progress`, `completion`, `quest_title`, `quest_description`, `quest_objectives`, gossip `text`, book `text` (id = the `page_text` entry), and the other kinds the runbook lists. `--ids` reads integers for id-keyed kinds and 16-hex keys for hash-keyed ones (`model.HASH_KEYED`).
   - Flags: `--ids FILE` (chosen lines), `--redraft` with `--ids` (fix drafted lines in place under the same draft name), `--redraft-older` (lines drafted under an older style version), `--held-back` (decision 6).
3. **`translate_lint` gates every draft row before import.** One reason per problem: coverage (`missing` / `duplicate` / `unknown_ref`), `not_japanese`, `tokens`, `leftover` (a `$` code, unknown `{word}` or `<a/b>` pair), `paragraphs`, `alignment_failed` (a Latin word the English lacks), `numbers_changed`, `counters`, `slash` (two renderings), `markup_changed:<difference>` (an HTML book page whose Japanese does not keep the English's tags in order, the same `markup.html_mismatch` that `wfj check` applies), `name_missing` and `glossary:<term>`. Failing rows are re-drafted once in a new context; rows that still fail are left out and ship as the live English. A row that passes only by keeping an English word to satisfy the check is held out by hand, not imported.
   - **`name_missing`** flags a capitalised English word (a name) the Japanese does not keep in English letters. It is the guard against katakana names ([principle 2](../architecture/principles.md#2-names-stay-in-english)), which no build check catches: `wfj check` has no `name_missing` rule, because applied to the store it would reject hand-written text that legitimately writes names differently. In a title-case line, a glossary title word directly before a listed name is part of the name ("Baron Aquanis") and must stay in English letters (`lint_names.titles_before_names`); the title used on its own is still translated ("The Baron's Demise" → 男爵の最期). The word must be kept whole (`王Lordaeron` does not keep `Lord`), and a Roman numeral (`Volume II`) is never a name a title word belongs to. `title_names` drops a trailing possessive `'s` or `'` (`Bingles'` → `Bingles`).
   - **The not-names list** (`pipeline/translation_not_names.tsv`, `<ref>\t<word>\t<English context>`, `--not-names PATH` to override). Book headings, letter greetings, plaques and quest titles capitalise ordinary words (`The Fall of Ameth'Aran`, `An Overdue Package`, `Unwelcome`), which `name_missing` cannot tell from names. Relaxing the rule would let katakana names through, so each flagged word is reviewed instead, and treated as **a name when in doubt**. An entry exempts one word on one row, keyed by the row's ref, so it lapses when that English changes. A row entry also exempts a `required` glossary term listed for that ref exactly as the lower-case term, where the word is used in another sense ("a rogue spark", "a rogue apothecary"); every other required term on the row is still checked.
   - Two counting rules for book text: the paragraph count reads the English and the Japanese the same way (a line of only spaces between two breaks is one break), and a word after a `\n\r` line break starts a sentence.
4. **The style version is in the draft name.** `expand --name <kind>-sg<N>` and `wfj import draft` (for the styled fields, `style.STYLED_FIELDS`) both refuse a name whose `sg<N>` differs from the style guide's `version:` line (`core/style.py`), so every machine line's `provenance.source` (`draft-gossip-sg3@2026-09-15`) records the prompt it was written under, with no schema change. The version is bumped when a rule changes what a draft should say; a note that only restates the glossary does not bump it.
5. **The glossary, with required terms.** `pipeline/translation_glossary.tsv` lists recurring words that are translated, not kept in English: titles and nouns used alone (`the Captain` → 隊長, `mayor` → 町長, `quartermaster` → 補給係), days of the week, the faith sense of `the Holy Light`, everyday words that recur in books (`diary` 日記, `report` 報告). It never lists a name; before a name a title stays English ("Mayor Oakley"). A term marked `required` (the race and class words, in the katakana `Core/Placeholders.lua` fills `{race}` / `{class}` with, and `goblin` → ゴブリン) must appear in exactly the glossary's spelling, or lint fails with `glossary:<term>`. Glossary words (and their plurals) are exempt from `name_missing` unless they stand directly next to a name word (`Captain Althea`, `Dark Lady`), where they are part of the name. "Goblin Engineer" / "Goblin Engineering", the capitalised specialization, stays English like other profession names.
6. **Held-back lines.** Where every hand-written variant of a line is rejected by the rules, and the line is a completion, or a description / objectives / title rejected as `truncated` or read by a person and set aside, the model translates the **whole** line and replaces that text. The truncated text is never extended by a splice (two translators' voices in one speech). A line rejected for other reasons only (a misspelled name) is a hand correction's job (ADR-012). A hand-written variant that ships is never touched.
   - **Recorded as rejects, not an accept.** `dev/rule_held_back --field completion|description|objectives --date <the decision's date>` (dry run by default; `--date` required; `--field` defaults to `completion`) writes the ADR-012 `ruling: reject` (with `by`, `date`, `note`) on every hand-written variant of each such line. ADR-014 §3 then no longer bars a machine variant (no unruled hand-written variant is left), and `decisions.carried` keeps the rulings across `make data`. The draft still has to pass `check` on its own merits. The set-aside text stays in `data/` as a ruled `reject` variant in `conflicts`.
   - **`cut --held-back`** selects exactly those lines, for the kinds in `HELD_BACK_KINDS` (completion, `quest_description`, `quest_objectives`, `quest_title`). Narrow it with `--ids` to the ruled lines, because without it `--held-back` also selects every undrafted line with no Japanese. `--ids` still brings along undrafted lines sharing a listed line's English.
   - **`validate --base` rule 2** accepts a hand-written → machine change when the line carries `ruling: accept` **or** when every hand-written variant on it carries `ruling: reject` (`core.decisions.hand_written_all_rejected`). One unruled hand-written variant still fails it (ADR-014 §5). The reject path covers only lines that shipped nothing at the base ref; a line that **shipped** hand-written text at the base fails rule 2 unless the machine line carries its own `ruling: accept`.
   - **A reject ruling is permanent.** A reject-ruled variant is never a candidate again, even alone on its line and even when it later passes the rules (`status.decide`: `rejected`, its own reasons or `ruled_reject`). A ruled line with no passing draft keeps showing the live English, not the text a person set aside.
7. **Rank between machine drafts: style version before import date.** `status._rank` orders passing variants by class, English paragraphs covered, then, between machine drafts, the higher `-sg<N>` right before the `@` in `provenance.source` (none counts as 0), then the newer `imported` date. A `--redraft-older` re-draft therefore wins over the older-version draft on the day it is imported, instead of tying into `duplicate_conflict`. Two drafts of the same version imported the same day under different names still tie.
8. **Model and critic.** The drafting model was chosen by a blind comparison of three current models on the same 50 rows, judged by two models with per-row shuffled labels; both judges ranked the chosen model's uncritiqued drafts above 4.8 of 5. There is **no critic pass**: the remaining errors were rule errors that lint and `check` catch mechanically. Its id is in every drafted line's `provenance.model`.
9. **Quest text is drafted from Classic Era English where Forever has not served it yet.** Over the quests both clients' quest caches hold, about 2% have English that Forever changed (after `normalize_v1`), and the beta opens content in waves, so waiting would leave most quest text English for weeks. Quest `title` / `objectives` / `description` is drafted from the Classic Era English, and a later Forever rewording shows the stale marker ([ADR-003](003-ship-stale-with-marker.md)) until re-drafted. Item and spell tooltip text waits for the Forever English.

## Consequences
- **Coverage is generated, not recorded here.** `make coverage` writes [docs/operations/coverage.md](../operations/coverage.md): what ships per surface and why the rest does not.
- **A redo is targetable.** Every machine line names its style version, so a later guide can re-draft older lines by source (`cut --redraft-older`), and a newer version's draft wins by rank. A single line is fixed in place with `cut --ids --redraft` under the same draft name.
- **Lint limits ship English, by design.** A capitalised common noun used for emphasis cannot be told from a name, so a correct draft of it fails `name_missing` and the line ships as the live English rather than weakening the name check (or it gets a not-names row once reviewed). Where a required class word is used in another sense ("rogue elements", "`dwarf` used as a verb"), a draft must not bend it into the class word to pass lint; such a page ships English or gets a not-names row.
- **Lines left in English by rule.** English that branches in a way one Japanese text cannot reproduce stays English (spell 5217, Tiger's Fury: "Requires Cat Form" switches colour by form). Test or junk English (`x`, `Hunter test quest2`, `[PH] Description`) and a line whose English is only `...` ship as the English. Text with no English of its own in any source cannot be checked, so the game's English shows.
- **Machine text is reviewed by rules, not by a person.** No critic model and no in-game read of these lines before merge. A person takes a line back with a `correction` (ADR-012, ADR-014 §7). Hand-written lines are audited against their English separately: corrections where the Japanese no longer matches, reject rulings and a redraft through `cut --held-back` where it is not worth keeping (`dev/audit_batch`, `apply_review --scope audit`).
- **The held-back rulings are data, not a flag.** They survive `make data` like any ruling. A later hand-written variant on one of those lines is unruled, so it bars the machine draft again and must pass on its own, which is the intended behaviour.

## Alternatives considered
- **A `style_version` field in provenance**: a schema change on every machine line; the draft name already carries it.
- **Draft per `(id, field)` instead of per unique English**: drafts repeated texts again, and lets identical English get different Japanese.
- **Leave `$` tokens for the model**: it would have to write the addon's placeholder form itself, and a Japanese `$G` pair cannot be expanded by the addon.
- **`ruling: accept` on the machine draft for held-back lines**: `accept` wins outright, so a draft failing `check` would ship, and re-importing under the same name drops the ruling (ADR-014 Consequences). Rejecting the set-aside text keeps every check in force.
- **Keep the human first paragraph and draft only the rest**: splices two translators' voices in one speech; rejected.
- **Relax `name_missing` for capitalised common nouns**: would let katakana names through; the few lines it blocks ship English instead, or get a reviewed not-names row.
- **A critic pass per batch**: both judges rated the uncritiqued drafts above 4.8 of 5, and the remaining errors were rule errors that lint and `check` catch mechanically.
