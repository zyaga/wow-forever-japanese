# Testing strategy

> What gets tested where, without a headless game: the pipeline (pytest), the addon (busted over a stubbed client), the contracts between them, and the in-game checklists only a person at the client can run.

## Scope
Pipeline (Python), the addon's Core (Lua, all pure or stub-driven), the shared normalize+hash contract, generated-data integrity, and the in-game checklist only a person can run.

## Automated tests and checks

### Running the tests

| Command | What it runs |
|---|---|
| `make test` | `test-py`, `test-lua` and `luac` |
| `make test-py` | pytest over `pipeline/` and `tests/python/` |
| `make test-lua` | busted over `tests/lua/spec/` (Lua 5.1 semantics) |
| `make coverage-py` | pytest under coverage.py; fails below `COV_PY_MIN` percent of the pipeline's lines |
| `make coverage-lua` | busted under luacov; fails below `COV_LUA_MIN` percent of the addon's logic lines |
| `make luac` | every addon Lua file parses, generated shards included |
| `make lint` | ruff, luacheck, the `Core/` frame-access gate, no English data in the addon, `wfj public-check` |
| `make validate` | the data gate: schema, provenance, collisions, referential integrity, regenerate-and-diff, placeholders, UI strings, objective fingerprints, readings |

Python tools run from the repository's virtual environment (`python3 -m venv .venv && .venv/bin/pip install -e "pipeline[dev]"`, from the repository root). The Makefile uses the main checkout's `.venv/bin/python` by itself when it exists, from every git worktree too, and `python3` otherwise. To run another interpreter, pass `PY=` with an absolute path: the recipes change directory before they run Python, so a relative path fails. The dev dependencies are pinned exactly in `pipeline/pyproject.toml` (pytest, ruff, coverage), and the Lua rocks (busted, luacheck, luacov and their dependencies) in `.github/lua-rocks.txt`.

### Coverage

Test coverage is measured, not estimated. `make coverage-py` runs the pytest suite under **coverage.py** (source `wfj`, configured in `pipeline/pyproject.toml`); `make coverage-lua` runs the busted suite under **luacov** (`.luacov` counts `Core/`, `UI/` and `Main.lua`, and leaves out the generated `Data/` and the tests). Each target fails when the total drops below its floor, `COV_PY_MIN` and `COV_LUA_MIN` in the `Makefile`. CI runs both on every pull request, in place of plain `test-py` / `test-lua`, in two jobs that run beside each other (`validate` for Python, `lua` for the addon), so a pull request waits for the longer suite, not both in a row.

How much of the *game* ships in Japanese is a different number: `make coverage` writes it to [Coverage](../operations/coverage.md), and `test_coverage.py` fails when that file is out of date.

### Pipeline: pytest

`tests/python/` holds about 120 test files, one or more per module, over committed fixtures in `tests/fixtures/` (excerpts of the predecessor files, pfQuest, wago CSVs, VMaNGOS as a generated SQLite file, quest-cache records, DB2 files and a synthetic local archive, a collector dump, JMdict). No test needs a game or the network.

- **Pure core**, table-driven: `normalize`, `hashing`, `language`, `align` (names, numbers, slots, name-list tails, inclusions and branches), `dedupe`, `status` (the decision table, one case per rule), `paragraphs` and the truncation rule, `specifiers`, `markup`, `placeholders`, `readings`, `glosses`, `style`, `decisions`, `fix_report`.
- **Emit and generate**: golden Lua text for every row shape (`test_lua_writer.py`), the slot map against `model.FIELDS` (`test_schema.py`), and `test_generate.py`: `plan()` equals the committed `Data/` byte for byte, a second run is a no-op, range-edge ids land in the right shard, emptied shards are deleted, the TOC block is rewritten, female variants and gender aliases, branch variants.
- **Import**: every importer over its fixture, with the source-owned and client-table merges, the served step (additive: an id any Forever build served keeps its English; the served record), the shrink guard, the source stamp, carried corrections, rulings and English baselines through a rebuild (`test_corrections.py`, `test_english_carry.py`), and the refusals that must write nothing. A player's collector send: the string decoder and its caps, every entry through the dump file's checks, finding the string or the attachment in an issue body, the check summary and its exit codes, and an intake equal to importing the same file (`test_collector_send.py`, `test_collector_send_github.py`).
- **Readers of client files**: BLTE frames, the local archive index and root (with blank-header entries), WDC5 tables, the hotfix cache, per-build column maps and their evidence, the quest-cache layouts per build (`test_wdb_reader.py`). `test_client_tables_install.py` runs against a real install only when `WFJ_WOW_DIR` is set.
- **Check and validate**: one fixture tree per validate rule (`test_validate.py`), the machine guard and ruling semantics, per-field English and the live-check baseline, the gossip and book rules, `test_check.py`'s floors over the committed corpus.
- **Committed data**: `test_data_integrity.py` and `test_ui_forever_health.py` read the real `data/`: every correction ships and is attributed, the UI dictionary resolves on Forever with no mismatched, ambiguous or unresolved key, the level-1 spell set has Japanese. Planning the committed store takes seconds, so `conftest.py` does it once per pytest session (the session-scoped `planned` and `plan_report` fixtures); every test that needs the committed plan takes it from there, and a test in `test_generate.py` fails when a test module plans the committed store itself.
- **The UI dictionary**: the curated key list and its curation rules (`test_ui_keys.py`), the inventory and its coverage (`test_ui_coverage.py`, `test_ui_inventory.py`, `test_ui_uninventoried.py`), exclusions and dispositions (`test_ui_exclusions.py`, `test_ui_dispositions.py`), the Forever window list and file map (`test_forever_windows.py`, `test_client_addons.py`), client-table families (`test_ui_client_families.py`), markup and families in the pipeline (`test_ui_markup_and_families.py`), spell subtexts (`test_ui_spell_subtexts.py`).
- **Translation batch tools**: `cut`, `expand` and the lint reasons (`test_translate_batch.py`, `test_translate_lint.py`), the style guide's version and examples (`test_style_guide.py`), the rulings tools (`test_held_back_*.py`, `test_baked_numbers_ruling.py`), review and audit (`test_apply_review.py`, `test_audit_batch.py`), the interface-text lint (`test_ui_lint.py`).
- **Guards on the addon source**: `test_forbidden_calls.py` (no protected call, layout call or Blizzard field write), `test_addon_no_harvest.py` (the addon never reads the client's caches), the TOC order (`test_toc_check.py`), luacheck grants (`test_luacheck_*.py`).
- **Project gates**: the release tooling and zip check (`test_release.py`, `test_package_check.py`), every workflow file (`test_workflows.py`: read-only default token, SHA-pinned actions, no expression inside a `run:` script, the release job order), the CI toolchain script and the composite action that runs it (`test_ci_toolchain.py`: the cache key, the retry on a miss, the pinned versions, both Lua jobs running the action before any `make`), `wfj public-check` (`test_public_check.py`), the licence and attribution files.
- **Accuracy**: `test_alignment_accuracy.py` gates precision of the name and number checks at 0.95 on a 200-row labelled sample (`tests/fixtures/alignment_sample.jsonl`); precision is 1.000 on the rows whose Japanese is unchanged since labelling.

Determinism is tested everywhere it matters: a frozen clock, `check` twice equals once, `generate` twice equals once, an import re-run is a byte no-op.

### Addon: busted

busted 2.3 under Lua 5.1: LuaJIT locally on macOS (Homebrew has no PUC 5.1), PUC Lua 5.1 in CI (`LUA=lua`), because luarocks under LuaJIT cannot load the luarocks.org manifest. `.busted` sets `ROOT = tests/lua/spec` and the pattern `_spec`. The rocks are dev-only; `.pkgmeta`'s ignore list keeps the shipped addon dependency-free.

The harness in `tests/lua/spec/`:
- `helpers.lua`: `loadChunk` with the `(ADDON, WFJ)` vararg, `loadChunks` for several files into one namespace, `loadPure(relpath)` (loads a chunk in a standard-library-only environment where any WoW global access raises: the purity proof for `Core/` modules), `H.uiSetup` / `H.uiTeardown` (build the UI index and translator as `Main` does), `H.collectorDeps`, `vectors()`.
- `loader.lua`: loads files in TOC order.
- `wow_stub.lua`: builds only the globals the addon touches, so anything missing fails loudly. It models frames and FontStrings (with call counters, so the addon's own writes are counted apart from the client's, and `Stub.fontSetFails` for a refused `SetFont`), `hooksecurefunc`, the key-state polls and bindings, the Settings API, tooltips with their line widgets and the `TooltipDataProcessor` path, ScrollBox callbacks, `C_Timer`, the unit and build APIs, and SavedVariables serialisation.
- Per-window stubs (`stub_*.lua`, `menu_stub.lua`, `gossip_client.lua`, `itemtext_client.lua`, `collector_session.lua`) replay Blizzard's own writers for their windows, taken from the Forever client's FrameXML, so a spec drives the addon the way the client would.

About 200 specs cover:
- **Core**, loaded pure: `hash_spec` (the parity gate over the shared vectors), `normalize_spec`, `align_spec` (every align vector, value fill, durations, textures, branch variants), `lookup_spec` (against the real generated shards), `translator_spec` (policy, markers, the gate, the quest live check), `surfacestate_spec`, `settings_spec`, `modifier_spec`, `placeholders_spec`, `collector_spec`, `collector_send_spec` (pending and the shipped filter, the three size modes, the sent marker), `readings_spec`, `glosses_spec`, `objectives_area_spec`, `state_spec`, `compat_spec`, the fix-report core (`recent_lines_spec`, `reports_spec`, `report_text_spec`), the UI string index (`uistrings_spec` and the `uistrings_*_spec` family: grammar, argument kinds, client-table families, numbered rows, owned keys, names, entry guards).
- **Rendering and surfaces**: `render_spec` (the desired-text registry, refresh, font retry), the quest window and quest map, tooltips (item, spell, aura, comparison), gossip and NPC speech, books, errors and system chat, the word card, and one spec per window module, driven through the stubbed writers. Each asserts Japanese on show, live English while the modifier is held, English again when the area or master switch is off, and no write to a widget the module does not own.
- **Load and settings**: `addon_load_spec` (TOC order, every module resolves, the guarded load sequence), `init_guard_spec` (one failing surface costs only itself), `options_spec`, `slash_spec`, `keycapture_spec`, `revealbinding_spec`, `fix_window_spec`, `collector_send_window_spec`, `minimap_button_spec`.

### Shared contracts

Three vector pairs, all regenerated by `make vectors`: `vectors/hash_vectors.{jsonl,lua}` (the normalize + hash contract; both suites iterate it, and a copy ships as `Data/Vectors.lua` for `/wfj debug hash`), `vectors/align_vectors.{jsonl,lua}` (names, name checks, numbers and number words, run through `core/align.py` and `Core/Align.lua`) and `vectors/report_vectors.{jsonl,lua}` (the fix-report text format, parsed in Python and written in Lua). Drift tests fail when a committed twin differs from a regeneration. Hand-written twins (the slot map in `Core/Const.lua` and `emit/schema.py`, the allowlist, the placeholder tokens, the UI families) are parity-tested from both sides.

### Generated data

`addon/…/Data/` is a build artifact: `wfj validate`'s regenerate-and-diff rule fails CI when the committed shards or the TOC's generated block differ from a regeneration of `data/`, so a hand edit, or a `data/` change without `make generate`, cannot merge ([principle 7](../architecture/principles.md#7-generated-files-are-never-edited-by-hand)). `make luac` parses every shard.

### Static checks

`luacheck` (`std="lua51"`, a curated `read_globals` of every WoW API used, so a new API is a reviewable diff; names reached through `Compat`'s injected environment are inventoried in `Core/Compat.lua` and the surface files instead; `bit`, `CreateFont` and every `GameFont*` / `SystemFont*` object are deliberately absent; `Data/` excluded), `make luac` (`loadfile` over every addon Lua file, so each one parses), `ruff` for Python. `make lint-core-gate`: no `CreateFrame(` / `_G[` / frame global under `Core/` ([principle 8](../architecture/principles.md#8-rendering-apart-from-data)). `make lint-public` runs `wfj public-check all`.

### Continuous integration

On every pull request `pr.yml` runs three jobs beside each other. `validate` sets up Python 3.14, restores the pinned Lua toolchain, then runs `make lint`, `make coverage-py`, `make luac`, `make toc-check` and `make validate` (with `--base origin/<base branch>`, so the provenance rule can compare against it; [Release](../operations/release.md)). `lua` restores the same toolchain and runs `make coverage-lua`; it needs no Python. `text` checks the pull request's wording (below). The toolchain steps live once, in the local composite action `.github/actions/lua-toolchain/action.yml`: restore from cache, build on a miss (each download retried once), save, put on `PATH`, `.github/scripts/lua-rocks.sh verify`. Both code jobs run it first.

**Pull-request gates beyond the make targets.** On pull requests only, CI also runs `wfj public-check pr` over the pull request's title, body, branch name and commit messages, and `wfj release changelog-gate --base origin/<base>`: a pull request that changes `addon/` or `data/` must add at least one line under `## Unreleased` in `CHANGELOG.md`, released sections may not change, and an added line may not carry a ticket id or a local path (docs, CI, tests and pipeline-only pull requests are exempt). When a pull request changes `data/`, a "Data delta" step writes `wfj stats --delta origin/<base>` to the run's job summary (a summary needs no write token; a pull-request comment would, and pull requests from forks get none). Every third-party action in every workflow is pinned to a full commit SHA.

**Release gates** ([Release](../operations/release.md), [ADR-046](../adr/046-one-action-release.md)): the Release workflow runs the whole pull-request workflow (`pr.yml`, reused through `workflow_call`) on `main` before it builds anything, and `wfj package-check` checks the built zip before anything is pushed or published. pytest covers the release tooling: `test_release.py` (the version rule, the refusals, resume, the changelog cut and notes, the pull-request changelog gate), `test_package_check.py` (the zip holds exactly the tracked addon files plus `LICENSE` and `ATTRIBUTION.md` under one `WoWForeverJapanese/` folder; every TOC-listed file present; the TOC version matches; the CurseForge project id is a number; no dependency field), and `test_workflows.py`, which reads every workflow file and the repository's own composite actions and guards: a read-only default token, the release job the only writer, no `pull_request_target` or `workflow_run` trigger, every third-party action SHA-pinned, no `${{ }}` expression inside a `run:` script, the CurseForge token only in the publish step (and the true/false check that it is set), no release on a tag push, the release's single optional `version` input, one release at a time, the job order plan → validate → release, the push only after the zip is checked, a resumed run skipping commit, tag and push, and the Makefile using the same packager pin as the workflow. `test_ci_toolchain.py` matches the pinned actions by name rather than by `@v4`.

## In-game checklists
No headless game exists, so what only the client can show is checked by a person in game, on the Forever client ([ADR-034](../adr/034-forever-is-the-only-target.md)). Addon comments point here as "the in-game check in docs/testing/strategy.md". The numbered checklist covers the core surfaces; the sections after it cover the windows and features one area at a time. Record what you see, including `/wfj debug` output, with the pull request or issue.

1. **Quest accept / progress / turn-in.** Japanese (quest 456's accept window shows its complete three-paragraph description with no `[未翻訳 / Not Translated]` banner); Alt → live English; release → Japanese; no clipping; scroll height correct after `SetText`. **Player placeholders:** quest 456's accept window shows the character's name in place of `{name}` (`御機嫌よう、<character name>。`) and the class in katakana in place of `{class}` (for example `若きドルイドよ`), no literal `{…}` token on screen; Alt shows the English; `/wfj debug` prints `placeholders: 0 unknown tokens seen`. **Truncated descriptions re-translated:** a fresh dwarf or gnome at Coldridge Valley opens quest 179 "Dwarven Outfitters"; the description is complete Japanese with the English paragraph breaks and no banner; holding Alt shows the live English.
2. **Quest map** (the quest log on Forever, `UI/QuestMap`): selecting another quest re-renders; Alt held *while* selecting; abandon / complete.
3. **Gossip** (ADR-017). **Translated lines:** talk to Conservator Ilthalaine in Shadowglen; his greeting shows in glyphs (no boxes), the rows below are spaced correctly with no overlap or gap (also on the first gossip window of the session and after scrolling), Alt shows the English, and `/wfj debug gossip` prints the greeting's key as `trusted`. Glyphs must still render after opening, after scrolling, and after a `QUEST_LOG_UPDATE` rebuild (accept or abandon a quest while the window is open at a gossip-and-quest NPC); this checks the [unverified] `UpdateTheme` / `RegisterFontString` question in ADR-017. Correct spacing shows that the measure-widget post-hooks run in the client. **Untranslated lines:** an NPC's greeting and options with no shipped row stay English with no visual change and no Lua error; an NPC with 8+ options scrolls normally (pooled rows re-initialize with their own text); a gossip-and-quest NPC's quest titles are unchanged; the quest window's greeting panel is unchanged apart from any shipped prose; after `/reload` the dump holds `gossip:` entries whose `n` lists creature ids (this confirms `UnitGUID("npc")` / `UnitGUID("questnpc")`); `/wfj debug gossip` prints a key for the greeting and each option. **Marker banner:** with `/wfj marker missing on`, an untranslated NPC shows `[未翻訳 / Not Translated]` in gold on the banner in the stone band between the title bar and the parchment, clear of the NPC name, the portrait and the greeting text; at an NPC with a friendship bar the banner stays hidden and the message is inline above the text; closing the window hides the banner.
4. **Tooltips:** bag item, equipped compare (Shift, `ShoppingTooltip1/2`), chat link (`ItemRefTooltip`), spellbook, action bar, vendor, loot. The description run is Japanese in place, the name line stays English (binding / stat / price lines are item 12), `Show()` refits, Alt restores every line; a spell tooltip shows the live numbers in the Japanese; `unaligned` and `stale` item / spell entries fall back on a value mismatch (a stale one that passes shows the stale marker inline); the `Use:` / `Equip:` / `Chance on hit:` trigger strings match the client's `ITEM_SPELL_TRIGGER_*` globals. Also: a food or drink with a four-digit value (a rendered thousands separator such as `1,992` must still translate); a spell tooltip with a `Next rank:` block; with a tooltip-ID addon installed, its appended line stays untouched (confirm `/wfj debug` says `spell description API: present`). Record whether the blank companion lines of a multi-line run (`Use:` + `Equip:` + quote) look acceptable; if not, per-line keys replace the run rule (ADR-010). A first hover that stays English and turns Japanese on the tooltip's 0.2 s refresh is the spell-description cache filling (`GetSpellDescription` returns `""` until then), not a gate failure. Aura tooltips are item 20.
5. **Markers:** with the missing marker on, an untranslated quest shows `[未翻訳 / Not Translated]` in gold in the band under the NPC name and the parchment text is untouched; a stale translation shows `[要更新 / English Changed]` there; the gossip window shows the same messages on its own banner (inline only while a friendship bar is shown, item 3); the quest map's details show the message inline above the title.
6. **Master key and slash:** the `WFJ_TOGGLE` binding and every slash verb; `/wfj debug hash` prints `hash vectors: 50/50 ok`; `/wfj debug quest 2` prints the Japanese title.
7. **Settings** from Esc → Options → AddOns and `/wfj config`; they survive `/reload` and logout; the downgrade path. The client templates and font objects resolve (a failure there is caught by `pcall` and reported by `/wfj debug`, and `/wfj` keeps working). The pages in detail are item 14.
8. **Collector:** the two-line disclosure appears once (not again after `/reload`); `/wfj collector` and `/wfj collector path` print the status and the path. After viewing a quest (accept / progress / turn-in), selecting it in the quest map and hovering an item and a spell, then `/reload`, `WTF\Account\<ACCOUNT>\SavedVariables\WoWForeverJapanese.lua` holds `WFJ_Collector` entries (`quest:`, `item:`, `spell:`, `npc:`; the `npc:` entries confirm `UnitGUID("questnpc")`); stored text uses `$N` / `$C` / `$R` / `$B$B`, never the character's name; `make import-collector DUMP=<that file>` succeeds with no rejections; a search of the file for the character's name and realm finds nothing. Hover the Hearthstone item, the Hearthstone spell and (on a shaman) Astral Recall: their descriptions name the bind location, and no `item:6948`, `spell:8690` or `spell:556` entry is written. Repeat a few quests on a second character of another class and race (ideally female, to see gender-dependent `$G` wording kept as shown) and compare the two dumps: the `$C` / `$R` lines agree, and any line that differs is a literal class or race word. String escaping of quotes inside `e` is not yet observed in a real dump. The cap message is not practical to reach in game (4 MiB); `collector_spec` covers it. Importing a dump can move quest and gossip hashes (`check` consults that English), so run `make check` after it and review the delta ([Collector](../systems/collector.md)).
   **Sending it** ([Collector sends](../operations/collector-sends.md)): `/wfj collector send` opens the send window with a count of lines and the steps; `/wfj collector status` shows `(N unsent)`. Copy the link (click it, Ctrl+C) and open it in a browser: the *Collected English* form opens with the box filled in (`WFJC1:…`). Submit it: within a minute the issue gets the `collector-ok` label and a comment of counts with no English in it. `make collector-intake ISSUE=N` imports it, and running it again changes nothing. Click **I sent it**, then `/wfj collector send` again: it says there is nothing new to send, and `/wfj collector send all` packs everything again. With a large dump (play a while, or a copied-in file of another character) the window shows a second box with the string to paste instead of a filled-in link: click it, Ctrl+C, paste it into the form, and check that the whole string arrived (it can be close to 60,000 characters) and the check reads it the same way. **File mode** (a dump too long to paste): the window shows the file step and path; zip the file, drag it into the form's box, submit; the issue gets `collector-ok`, and `make collector-intake ISSUE=N` downloads the attachment and imports it. In file mode after recording new lines since login, the window says how many are not in the file yet and asks for `/reload` first. On the beta, the English Collector settings page's path and `/wfj collector path` name `_classic_beta_` instead of `<client folder>` (this confirms `IsBetaBuild()` is true there).
9. **Memory and login time:** `/wfj debug`'s `memory:` line (also in the settings-panel header) about ten seconds after `/reload`, against a baseline without the addon; login time. Readings for every line add about 10 MB of client memory; record the total with every data release.
10. **Combat:** open tooltips, a quest frame and the gossip window mid-combat; no protected-function errors (for gossip: scroll the list and hold Alt with a translated row, since `FullUpdate(true)` runs from the addon's code, ADR-017).
11. **Client parity:** `## Interface` accepted; every Compat candidate resolves (`/wfj debug` prints unresolved widgets).
12. **Interface text** (ADR-015): a bag armor piece, a weapon, a spell (spellbook) and the character sheet show translated structural lines with correct numbers; the quest accept / progress / turn-in windows and the quest map's details pane show Japanese headers and buttons; Esc shows a Japanese game menu; buttons keep glyphs on hover and when disabled; Alt shows English everywhere; `/wfj area interface off` restores English; combat with the world map's quest panel open raises no blocked-action error; `/wfj debug ui` reports 0 mismatched / 0 unresolved. On each covered window and a few tooltips, `/wfj debug ui scan` lists no `hook?` entry; a `key?` entry is triaged (a name, prose, or a string to add to the inventory's exclusions or keys). Taint: open and close Esc in and out of combat and click Options / AddOns / Macros / Log Out (cancel); no "WFJ: the game blocked" line, and no `blocked`, `turned` or `write` entry in the problem log after `/reload`. Hover cost: hold a tooltip over a bag item for a few seconds; no stutter.
13. **Always-visible windows** (ADR-016). The window-by-window steps are the [Forever re-target checklist](#forever-re-target-checklist) and the [Forever window checklist](#forever-window-checklist); run item 11 with them. Also:
    - **Per window.** `/wfj debug ui scan` lists no fixed English label (each remaining text is a name or a listed exclusion). Tabs are not clipped and keep their glyphs when selected. Hover the micro buttons, stats, resistances, empty equipment slots, bag slots, repair buttons and bank bag slots. Alt shows English everywhere; `/wfj area interface off` restores English.
    - **Debug and taint.** `/wfj debug ui` reports 0 mismatched / 0 unresolved / 0 unsupported. Never turn on `taintLog` on Forever (it breaks every post-hooked method; [Client limits](../architecture/client-limits.md)). Open every window, then cast from the spellbook in combat, shapeshift in combat with the spellbook open (druid) and use a bag item in combat. No "WFJ: the game blocked" line in chat, and after `/reload` the problem log has no `blocked`, `turned` or `write` entry ([Diagnostics](../systems/diagnostics.md#tracing-a-blocked-action)).
    - **Spellbook to action bars in combat** (ADR-058). On a rogue (or a warrior): learn a spell at the trainer, open the spellbook, switch tab, flip a page, hover three spells, close it, stealth (or change stance) and attack a mob. **Pass:** no "WFJ: the game blocked" line, the bars stay in place, and after `/reload` no `turned` / `write` / `blocked` entry. The spell subtexts ("Rank 1", "Passive") are English by design.

2. **A long page scrolls.** On a page whose Japanese runs longer than the window: the scroll bar appears and the last line can be scrolled into view, with a little space below it. **Fail:** the text cut off at the bottom with no scroll, or a scroll range far longer than the text.
3. **Word card.** Point at a kanji word on that page. **Pass:** the word is tinted and the word card shows above it (reading, dictionary form when different, a meaning). `/wfj glosses off` → the reading-only box; `/wfj glosses on` again. `/wfj readings off` → nothing on hover; `/wfj readings on` again.
4. **Alt.** Hold Alt: the English page shows in the client's own layout and nothing is drawn on hover; release: the Japanese and the card come back.
5. **Page turn.** On a book with several pages, Next → the next page's own Japanese (never the previous page's text left on screen); Prev → back. Point at a word on the new page: the card fits that page's words.
6. **An HTML page.** Open a page with headings (a large-parchment book or plaque): **Pass:** it keeps the client's own layout (headings keep their sizes) and no word card shows on it.
7. **Area text in the tracker / quest log.** Take a quest with an exploration or event objective and track it; open the world map's quest list and its details. **Pass:** the objective line shows Japanese, with any count kept where the client wrote it; hovering it shows no word card. Record where the line appeared (tracker, quest list row, details pane). `/wfj debug objective` prints `shipped N (objective n · area n) · indexed N · ambiguous N` with `area` above 0.

8. **Wrapping and hover edges.** On a long Japanese page the lines wrap inside the page at any character (no line runs past the right edge). Scroll a long page part way: pointing just below the visible window (over Prev / Next or the world) shows no word card.

**Not level-1:** most exploration and event objectives are on quests a new character cannot take yet; check step 7 when one comes up and record the quest id and where its line appeared.

### Fix reports checklist
The minimap button, the fix window, the one-language settings pages and the tooltip-frame word card ([Fix reports](../systems/fix-reports.md), [Settings](../systems/settings.md), [ADR-045](../adr/045-player-fix-reports.md)). On a fresh level-1 character with no quests, out of combat. The window, tooltip, menu and settings pages are in Japanese; holding Alt (the reveal key) or turning translation off shows their English; English names are given below in brackets.

1. **The button is there.** After login, the addon's 字 medallion sits on the minimap's edge (lower left by default), centred in its ring. Hover it: a tooltip titled *WoW Forever Japanese* reads 「左クリック：翻訳を報告 ・ 右クリック：メニュー」. Move off, hold Alt and hover again: "Left-click: report a line · Right-click: menu". **Fail:** no button, the icon off-centre in the ring, or the button off the minimap's rim.
2. **Drag keeps its spot.** Drag the button part way around the minimap; it follows the rim. Release, then type `/reload`: the button is where you left it. Dropping it after a drag does not open the fix window.
3. **Right-click menu.** Right-click the button: a menu titled *WoW Forever Japanese* with five Japanese entries: *翻訳オン* (Translation on), *翻訳を報告* (Report a line), *不具合・提案を報告* (Report a bug or idea), *設定* (Settings), *このボタンを隠す* (Hide this button). Close it, hold Alt and right-click again: the same five in English.
   - *翻訳オン* (checked): click it → the quest text and labels go English, and the next time the menu or the fix window opens it is in English too; open Esc → Options → AddOns → WoW Forever Japanese: the page is in English and *Enable translation* is off. Right-click the button again: the checkbox is unchecked; click it → Japanese is back everywhere, and the settings checkbox is on again.
   - *翻訳を報告*: the fix window opens.
   - *不具合・提案を報告*: the report window opens ([Bug and idea reports checklist](#bug-and-idea-reports-checklist)).
   - *設定*: the addon's settings page opens.
   - *このボタンを隠す*: the button disappears.
4. **Bring it back.** With the button hidden, open the settings page: 「ミニマップにボタンを表示（翻訳の報告）」 (Show the minimap button) is unchecked; check it → the button returns at its saved spot. Also try `/wfj minimapbutton off` then `/wfj minimapbutton on`: the reply names the setting and the button hides and returns.
5. **Addon dropdown entry.** Click the minimap's addon dropdown (the addon list button on the minimap). *WoW Forever Japanese* is listed with the 字 icon. Hover it: the same tooltip. Left-click: the fix window opens. Right-click: the same menu. Record whether Forever's minimap shows the dropdown at all.
6. **The window looks like the game's.** The fix window has the game's window frame with the title 翻訳の報告, and three tabs in the strip above the panel: 翻訳 · 送信待ち（0） · 報告を送る. The 翻訳 tab has round radio buttons すべて (selected) · クエスト・会話 · ツールチップ · 画面の文字 and a list with a slim scroll bar. Everything is in one font, nothing cut off or overlapping. Hold Alt: every label switches to English (Report a translation; Translations · Pending (0) · Send report; All · Quests & NPCs · Tooltips · Windows); release: Japanese again. Clicking a radio's own word selects it, never its neighbour. The window sits above the beta's Issue Reporter button, never under it.
7. **Rows appear, in order.** Leave the window open and talk to the first quest giver, open the first quest (read the quest text): its lines appear in the list without reopening. Then talk to an NPC with a greeting (a guard or a vendor). With *すべて* selected the NPC greeting comes first (the newest), then the quest's lines in on-screen order: title, text, objectives. Each row: the type (クエスト, NPCの会話) on the left and the start of the line as it read on screen (your character's name filled in, no [未翻訳] / [要更新] marker). No English text anywhere. Hover an item, open the character sheet, then pick *ツールチップ*: the item's lines; *画面の文字*: the window's labels; *クエスト・会話*: only the quest and NPC lines, still there.
8. **A report with a reason only.** Click the quest text row. The edit panel shows one large box (a dark field with a slim scroll bar) holding the line as the addon stores it (a name placeholder shows as `{name}`), then the reasons as radio buttons, a two-row note box and the buttons *保存* (Save), *戻る* (Back). Pick *不自然な日本語* (Awkward / unnatural; picking another reason moves the selection), leave the box as it is, click *保存*: the window moves to *送信待ち（1）* with 「保存しました。「報告を送る」から送れます。」.
9. **A report with changed Japanese.** Back on *翻訳*, click the NPC greeting row, pick *誤字・表示の崩れ* (Typo / broken text), change one character in the box, type a note, click *保存*: *送信待ち（2）*; its row shows the type and the reason on the left and your edited Japanese on the right. Pressing Enter in the note box leaves it. Clicking *保存* with no reason picked says 「先に、どこがおかしいかを選んでください。」.
10. **Alt while typing.** Click into the box, hold Alt: the labels stay as they were (the client sends no modifier event while a text box has focus). Click outside the box, hold Alt: English. Record what you saw.
11. **They survive `/reload`.** Type `/reload`, open the window again: *送信待ち（2）* lists both. *翻訳* is empty until you read something again (it is memory only).
12. **Send report.** Click *報告を送る* (Send report): four numbered steps. Step 1: the form address in a copy box: click it, Ctrl+C. Step 2: a box with a block starting `WFJ-REPORT 1`, one `fix …` line per report (the second with `note …` and `ja …` lines), ending `end 2`; clicking it selects all of it, then Ctrl+C. Step 3 says to paste and submit. Step 4: *送信済みの報告を消去* (Clear sent reports) on the same line.
13. **Paste into the issue form.** In a browser, open the address from step 1 (the *Translation report* form), paste into *Report* and look at the preview: the block is whole, from `WFJ-REPORT 1` to `end 2`. Do not submit unless a real report is wanted; if you do, the bot comments within about a minute with `Report read: 2 fix(es)` and adds `report-ok`.
14. **Clear sent reports.** Click *送信済みの報告を消去*: it changes to 「もう一度クリックで2件を消去」; click again within 5 seconds: 「2件を消去しました」, *送信待ち（0）*, and the Send report page now says how to save a report instead of the steps.
15. **Settings pages.** Esc → Options → AddOns: *WoW Forever Japanese* is already expanded, with *English Collector* and *About & Help* under it; the category list switches pages (no link buttons on the pages). Each page title is one language, gold; section headers are gold on a faint band with a gold rule; checkboxes are the game's settings checkboxes; every label is Japanese, and holding Alt shows English (as does translation off). On the main page, the modifier and toggle-key buttons have the key-binding look, and *キーを設定* (Set key) and *解除* / Unbind sit side by side on one line. The collector page's status line is in the page's language (状態: オン・N件・…); `/wfj collector status` still prints English. The About page has the *翻訳を報告* (Report a line) row, then 「不具合や提案は、ここから送れます。」 (Something not working, or an idea? Send it from here.) with a *不具合・提案を報告* (Report a bug or idea) button under it. Nothing overlaps, and no page scrolls.
16. **Word card and reading box.** Point at a kanji word in the quest text: the reading box and, for a word with a meaning, the word card are drawn in the game's tooltip frame (the same border as an item tooltip), the text inside the border, not touching it.

17. **A typed `|`.** Open a line, type `a|b` in the note, tick a reason, press *保存* (Save), then open *報告を送る* (Send report). **Pass:** the report's `note` line reads `a\x7cb` (one `\x7c`). If it reads `a\x7c\x7cb`, the edit box returned the pipe doubled; record it (the fix would collapse `||` before saving).
18. **Hold Alt, then let go.** With the quest text on screen, hold Alt and release it, then open the Translations tab. **Pass:** the list is in the same order as before (the quest's lines were not moved or doubled).

**Also:** Esc closes the window; `/wfj fix` opens it; the AddOn List's *設定* (Settings) button and its tooltip are in one language.

### Bug and idea reports checklist
The report window and the capture of the addon's own Lua errors ([Fix reports → Bug and idea reports](../systems/fix-reports.md#bug-and-idea-reports), [Diagnostics](../systems/diagnostics.md#the-addons-own-lua-errors), [ADR-057](../adr/057-catching-the-addons-own-lua-errors.md)). On a fresh level-1 character with no quests, out of combat, with no BugSack or other error addon enabled. The window is in Japanese; holding Alt or turning translation off shows its English; English text is given below in brackets.

1. **Open it.** Type `/wfj bug`. A window with the game's frame opens, titled 不具合・提案を送る (Report a bug or an idea), with two round radio buttons at the top: *不具合* (Bug, selected) and *提案* (Idea). Hold Alt: every label switches to English; release: Japanese again. Clicking a radio's own word selects it.
2. **No errors yet.** The summary line reads 「新しい Lua エラーはありません。ビルドとバージョンを送ります。」 (No new Lua errors from this addon. Build and version go with it.). Step 1 holds a link in a copy box: it starts `https://github.com/zyaga/wow-forever-japanese/issues/new?template=bug-report.yml&client-build=` and ends with `&addon-version=` and the addon's version, with no `&errors=`. Step 2 says the form opens filled in, step 3 says to write what happened and submit. There is no I sent it button and no step 4.
3. **The link opens the form.** Click the link, Ctrl+C, paste it into a browser while signed in to GitHub: the *Bug report* form opens with the client build (as `1.60.1.<build number>`) and the addon version filled in. Do not submit unless a real bug is wanted.
4. **Idea and back.** Click *提案* (Idea): the summary reads 「提案やコードの変更は GitHub に送ります。」 (Ideas and code changes go to GitHub.), the link is `https://github.com/zyaga/wow-forever-japanese/issues/new?template=idea.yml`, and only two steps show, the second 「2. 提案を書いて、GitHub で Issue を送信します。」 (Write your idea, then submit the issue on GitHub.). Click *不具合* (Bug): the bug summary, link and three steps come back. Nothing overlaps in either mode.
5. **Other ways in.** Press Esc: the window closes. Right-click the 字 minimap button and choose *不具合・提案を報告* (Report a bug or idea): it opens on Bug. Esc → Options → AddOns → WoW Forever Japanese → About & Help, click *不具合・提案を報告* under 「不具合や提案は、ここから送れます。」: it opens on Bug.
6. **Errors from elsewhere pass through and are not kept.** Type `/wfj log` and note the last line, `errors: N recorded, M not sent (/wfj bug)`. Turn the game's Lua error window on and raise an error that is not from this addon:
   ```
   /console scriptErrors 1
   /run error("WFJ test")
   ```
   **Pass:** the game's Lua error window shows `WFJ test`, its first line naming the `/run` text (`[string "error("WFJ test")"]:1:`), not a file of this addon; no `WFJ: the addon hit a Lua error.` line in chat; `/wfj log` ends with the same `errors:` counts as before; `/wfj bug` still says no new Lua errors. **Fail:** no error window (the addon swallowed the error), or the counts went up. Then turn the window off again: `/console scriptErrors 0`.
7. **Slash list.** On the About page, the slash list has `/wfj bug  (report a bug or an idea)`. Type `/wfj`: the footer names `/wfj bug`.

**When a real addon error happens** (in any session, at any level): one chat line `WFJ: the addon hit a Lua error. /wfj bug reports it.`, once per session. `/wfj bug` then says 「このアドオンの新しい Lua エラー N 件を報告に含めます。」 (N new Lua errors from this addon go with the report.), the link ends with `&errors=` and the error text, and *送信しました* (I sent it) shows on step 4. Open the link: the form's Lua errors field holds `1) 1 time, first <time>, last <time>`, the message (naming a file under `WoWForeverJapanese/`) and its stack (empty for an error a setup step caught itself), with your character's name written as `<name>`. If the window shows a second box instead (the text too long for the link), the field is empty and the box's text pastes into it. After clicking I sent it, the window says how many were marked and a new `/wfj bug` says no new Lua errors.

**Secret values (unverified, record what you see).** The client's own handler skips its log (`addframetext`, `C_Log.LogErrorMessage`) for an error whose message it may not read under taint, and this addon's wrapper is insecure code in that path. When the game's Lua error window (with `scriptErrors` on) shows an error with an empty or missing message, note the error count and the window's text, then `/wfj log`: record both. Nothing on a level-1 character is known to raise such an error.

**With BugSack (optional, needs another addon).** Enable BugSack, `/reload`, type `/wfj bug`: the summary reads 「別のアドオン（BugSack など）がエラーを取得中。そこから貼り付けてください。」 (Another addon (BugSack or similar) catches Lua errors: paste ours from it.). Errors this addon kept before BugSack was enabled still go in the link, with *送信しました* (I sent it) on step 4. Turn BugSack off again afterwards.
